# 07 · 分词器压缩率要实测，别信 README

## 现象
README 写 BPE 压缩率 "~4.2x"，实测同一词表只有 **1.50x**。

## 根因
1. 数字是记忆里的，没实测过（算错/记错）。
2. 在**语料子集**上训 BPE 会低估压缩率：子集太小，合并学得少，
   测出的压缩率系统性偏低。子集只适合看**相对趋势**，不能当真值。

## 修复
- 报告压缩率 = **全量词表 + 同一份评估文本**实测：

```python
tok = Tokenizer.from_file('data/chinese/tokenizer.json')
text = open('data/chinese/shareai_dialogue.txt', encoding='utf-8').read()[:200000]
print(f'{len(text) / len(tok.encode(text).ids):.2f}x')
```

- 选词表大小（实验）用子集对比相对趋势可以，但**对外报数字用全量实测**。
- 跨 tokenizer 比压缩率时，训练语料和评估文本必须一致。

## 怎么避免
**性能数字必须实测**，尤其涉及"我之前跑过/README 写过"的记忆。
本文档目录里的笔记也一样：数字要么给出实测命令，要么标"近似"。
