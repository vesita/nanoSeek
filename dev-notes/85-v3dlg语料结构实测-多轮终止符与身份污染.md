# 85 · v3_dlg 语料结构实测：多轮占比、终止符覆盖、身份污染

**日期**：2026-09-16 夜（`base_v3_mask` 训练进行中，等结果的空档）
**证据强度**：**全量计数**（不是抽样）—— 三个结论都是对整个 `v3_dlg` 的**穷举统计**，
不是估计。命令附在每节末尾，可逐字复现。

背景：`configs/base_v3_mask.yaml`（答案段掩码实验）跑到一半时，我去核对它的**前提**是否成立。
核对过程中撞出三条与"模型为什么不会自主对话"直接相关的**语料事实**。
它们与本次训练结果无关，所以先单独落档。

## 0. 为什么要现在核：掩码实验的一个隐藏前提

`base_v3_mask.yaml` 的自变量是 `use_loss_masking: true` + `mask_mode: eos_line`，
其规则是「token 所在的**行**内含 `<eos>`/`<cont>` ⇒ **整行**算 loss」。
设计时我写的推论是：

> 在 `A：…\nB：…<eos>` 里，**问题行不含终止符 ⇒ 天然被排除**，只有回答行算 loss。

★ 这个推论**依赖一个没人验过的前提**：**每一行回答都带终止符**。
若一个多轮块里只有**最后一句**回答带 `<eos>`，那么 `eos_line` 会把**前面所有轮的回答**
一起划进 -100 ⇒ 掩码臂会**丢掉大部分监督信号**，实验结论会完全反过来读。
（这正是 §5.9「关键词判据接线前先看会被翻转的样本」的同族风险：
规则表达式写对了，**数据形状**假设错了。）

**实测结论：前提成立** —— 终止符**贴在每一行回答的末尾**，不漏中间轮。见 §2。

## 1. ★ v3_dlg 是**真正的多轮语料**，且多轮占绝对多数（按字符）

按「一个块内有几行 `用户：`/`模型：`」统计（**行数 = 2 即单轮问答**）：

| 源 | 块数 | 2 行(单轮) | 3~4 行 | ≥5 行 | **≥5 行占字符** |
|---|---:|---:|---:|---:|---:|
| `belle_multiturn.txt` | 53,686 | 0.0% | 0.0% | 100.0% | 100.0% |
| `dailychat_dialogue.txt` | 622 | 0.0% | 100.0% | 0.0% | 0.0% |
| `escov_zh.txt` | 608 | 0.0% | 0.0% | 100.0% | 100.0% |
| `glm_dialogue.txt` | 42,486 | 0.0% | 53.3% | 46.6% | 73.2% |
| `kdconv_dialogue.txt` | 2,438 | 0.0% | 5.9% | 94.1% | 95.5% |
| `lccc_dialogue.txt` | 149,903 | 0.0% | 90.4% | 9.5% | 19.8% |
| `multi_turn_dialogue.txt` | 1 | 0.0% | 0.0% | 100.0% | 100.0% |
| `sharegpt_zh_38k.txt` | 38,247 | 0.0% | 56.5% | 43.5% | 78.2% |
| `wildchat_zh.txt` | 3,126 | 0.0% | 0.0% | 100.0% | 100.0% |
| **合计** | **291,117** | **0.0%** | **62.1%** | **37.9%** | **81.7%** |

读法：**没有单轮块**这个巧合是因为 v3 阶段切块时已按会话聚合（一个块 = 一段会话），
单轮问答在这里表现为 **2 行块**（上表第 3 列）。⇒
**61.8% 的块是多轮，且占 81.7% 的字符** —— 多轮不是边角料，**它就是主体**。

⚠ **§5.11 提醒**：本表**不能**与 AGENTS §6.4 的「72.6% 的对话 block 恰好 1 轮」并排读 ——
那个数是 **v2 整库 25 源**口径（含大量非对话源），本表是 **v3_dlg 9 源**口径。
换源集合 = 换尺子。

复现：
```bash
.venv/bin/python - <<'PY'
import collections, glob, os
for p in sorted(glob.glob('data/chinese/stages/v3_dlg/*.txt')):
    txt=open(p,encoding='utf-8',errors='replace').read()
    blocks=[b for b in txt.split('\n\n') if b.strip()]
    d=collections.Counter(); sz=collections.Counter()
    for b in blocks:
        n=sum(1 for ln in b.split('\n') if ln.startswith(('用户：','模型：')))
        k=1 if n<=1 else (2 if n==2 else (3 if n<=4 else 5))
        d[k]+=1; sz[k]+=len(b)
    T=sum(d.values()); C=sum(sz.values())
    print(f"{os.path.basename(p):26s} {T:8d} {100*d[2]/T:6.1f}% {100*d[3]/T:6.1f}% {100*d[5]/T:6.1f}% {100*sz[5]/C:8.1f}%")
PY
```

## 2. ★★ 终止符**贴在每一行回答末尾** —— 掩码前提成立（这条救了那个实验）

★ 关键：**跑在 `.txt` 上会得到 0，结论完全错**。`data/chinese/stages/v3_*/` 里的
`.txt` 是**标注之前**的文本，`<eos>`/`<cont>` 是 `annotate_replies` 在**建 bin 时**加的。
在 `.txt` 上 grep 终止符 ⇒ **全 0**，据此会误判"掩码会全 False ⇒ loss NaN"。

必须在 **bin** 上量。`train_char_v3_dlg.bin`（uint16，114,228,196 token）全量计数：

| 机制 token | 数量 | 占 token |
|---|---:|---:|
| `<eos>`(128) | 626,925 | 0.5488% |
| `<cont>`(130) | 163,989 | 0.1436% |
| `<resp>`(140) | **0** | 0% |
| `<topic>`(141) | **0** | 0% |

把块首解码出来看，格式是（`skip_special_tokens=False`）：

```
"写一篇关于环保的文章。"\n"环保意识逐渐深入…共同努力！"<eos>\n
"提取最重要的观点。"\n"重要观点：…等等。"<eos>\n
"A：请你为我写一篇关于太空探索的文章。"\n"B：好的，请问…思路吗？"<cont>\n
"A：请写一篇介绍人类太空探索历程的文章…"\n"B：好的，以下是…"<eos>\n
```

⇒ **终止符在闭合引号之后、换行之前，落在回答那一行上**；提问行不含终止符。
于是 `eos_line` 规则在**多轮块里也逐轮命中**，不会只留最后一句。
**掩码臂的前提成立**，实验可以照原判据读。

★ 顺带一个交叉验证：终止符 790,914 个 ≈ 回答行数；回答行平均 ~76 token
⇒ 0.5488%+0.1436% 的终止符密度**恰好**支撑 `mask_density_probe` 量到的
**53.3% 有效 token**（同源两个独立口径自洽）。

复现：
```bash
.venv/bin/python - <<'PY'
import numpy as np
a=np.memmap('data/chinese/train_char_v3_dlg.bin',dtype=np.uint16,mode='r')
n=a.shape[0]; print('total',n)
for k,i in (('<eos>',128),('<cont>',130),('<resp>',140),('<topic>',141)):
    v=int((a==i).sum()); print(f'{k:8s} {v:10,} ({100*v/n:.4f}%)')
PY
```

**纪律提炼**：量语料前先问「**这个符号是在哪一层加进去的**」——
`clean_v3/*.txt`（清洗产物）→ `stages/v3_*/*.txt`（切阶段）→ `*.bin`（tokenize + **标注**）
是三层，同一件事在三层的答案可以完全不同。

## 3. ★★ 身份污染**集中在最大的那个源里** —— 模型自称 ChatGPT 是**训出来的**

`sharegpt_zh_38k.txt` 是 v3_dlg 里**最大的源**（143.7 MB / 全部 ≈228 MB），
而它**几乎全是**围绕「你是不是 ChatGPT / 你是 OpenAI 训练的模型」的对话：

| 源 | 大小 | `openai`/`chatgpt` | `语言模型` |
|---|---:|---:|---:|
| `sharegpt_zh_38k.txt` | **143.7 MB** | **15,863** | **9,592** |
| `belle_multiturn.txt` | 71.4 MB | 0 | 1,283 |
| `wildchat_zh.txt` | 28.8 MB | 720 | 0 |
| `lccc_dialogue.txt` | 22.7 MB | 0 | 0 |
| 其余 5 源 | ~5 MB | 0 | 15 |

块首那段原文就是教科书例子（`用户：你不是ChatGPT吗？` / `模型：不，我不是Chatgpt。
我是由OpenAI培训的一种大型语言模型…`），且夹杂**俄语**（`свинья`）与长篇越狱角色扮演。

⇒ **"模型说自己叫 ChatGPT / 是 OpenAI 训练的"不是幻觉，是语料里 ~2.5 万条直接陈述训出来的。**
这解释了 `analysis/B_ood_prompts.txt` 里身份类提示词全线失败的现象，
也意味着：**人格段（小寻）在跟 2.5 万条反向陈述对抗** ——
人格段 900 步打不过它是**必然**，不是配方（lr/epoch）的锅。

⇒ 这是一个**便宜且高杠杆**的修法（比"扩语料"便宜得多）：
清洗或改写 `sharegpt_zh_38k.txt` 的身份陈述，或整源降权/剔除。
★ **改这个源要重建 bin 并重跑污染率/有效 token 验收**（§5.10、§9 `build_stages`）。

复现：
```bash
cd data/chinese/stages/v3_dlg
for f in *.txt; do o=$(grep -o -i -E "openai|chatgpt" "$f" | wc -l); \
  l=$(grep -o "语言模型" "$f" | wc -l); echo "$f $o $l"; done
```

## 4. 与"自主对话"直接相关的第三条：**`<topic>` 一个都没有**

bin 里 `<topic>`(141) = **0**，`<resp>`(140) = **0**。
⇒ 「主动换话题」的机制（`dialogue_stream.py` 的 `new_topic=True`、id 141）
在 **v3_dlg 上完全没有训练信号** —— 它是**为陪聊语料准备的，而陪聊语料没接上它**。
「自主对话」里的**自开话题**这一维，在当前语料下**不可能**被学到，
判据（`eval_multiturn` 的自开轮次率）因此也只会读到语料的先验。

## 5. 三条结论合起来，对"模型为什么不会自主对话"的读法

1. **多轮结构在**（61.8% 的块、81.7% 的字符）⇒ 之前"语料是多轮拼盘、没有承接"的
   印象**需要收窄**：`analysis/corpus_quality_v2.md` 表 7 用的 **8-gram 承接**是
   **表层**代理，而 `用户：继续` → 接着写下一段这种**语义承接本来就不共享 8-gram**。
   ⇒ **"Δ 中位数 0.0000"不能推出"没有语义依赖"**，该文 §9 自己也这么写了。
2. **监督口径没问题**：终止符逐轮覆盖 ⇒ 掩码臂不会丢中间轮。
3. **但有两块硬缺口**：① 语料的**主体**在教"我是 ChatGPT"；
   ② 「自开话题」这一维**零信号**。

⇒ 对"模型怎样才能自主对话"，优先级被这三条改写了：
**先修"训在教的身份"与"零信号的能力"，再谈加步数**。
（加步数会把 §3 的反向身份陈述学得更牢。）
