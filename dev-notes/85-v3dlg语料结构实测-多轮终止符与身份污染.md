## 0. 为什么要现在核：掩码实验的一个隐藏前提

`base_v3_mask.yaml` 的自变量是 `use_loss_masking: true` + `mask_mode: eos_line`，
其规则是「token 所在的**行**内含 `<eos>`/`<cont>` ⇒ **整行**算 loss」。
设计时我写的推论是：

> 在 `A：…\nB：…<eos>` 里，**问题行不含终止符 ⇒ 天然被排除**，只有回答行算 loss。

★ 这个推论**依赖一个没人验过的前提**：**每一行回答都带终止符**。
若一个多轮块里只有**最后一句**回答带 `<eos>`，那么 `eos_line` 会把**前面所有轮的回答**
一起划进 -100 ⇒ 掩码臂会**丢掉大部分监督信号**，实验结论会完全反过来读。
（这正是 §5.9「关键词判据接线前先看会被翻转的样本」的同族风险：
规则表达式写对了，**数据形状**假设错了。）

**实测结论：前提成立** —— 终止符**贴在每一行回答的末尾**，不漏中间轮。见 §2。

## 2. ★★ 终止符**贴在每一行回答末尾** —— 掩码前提成立（这条救了那个实验）

★ 关键：**跑在 `.txt` 上会得到 0，结论完全错**。`data/chinese/stages/v3_*/` 里的
`.txt` 是**标注之前**的文本，`<eos>`/`<cont>` 是 `annotate_replies` 在**建 bin 时**加的。
在 `.txt` 上 grep 终止符 ⇒ **全 0**，据此会误判"掩码会全 False ⇒ loss NaN"。

必须在 **bin** 上量。`train_char_v3_dlg.bin`（uint16，114,228,196 token）全量计数：

| 机制 token | 数量 | 占 token |
|---|---:|---:|
| `<eos>`(128) | 626,925 | 0.5488% |
| `<cont>`(130) | 163,989 | 0.1436% |
| `<resp>`(140) | **0** | 0% |
| `<topic>`(141) | **0** | 0% |

把块首解码出来看，格式是（`skip_special_tokens=False`）：

```
"写一篇关于环保的文章。"\n"环保意识逐渐深入…共同努力！"<eos>\n
"提取最重要的观点。"\n"重要观点：…等等。"<eos>\n
"A：请你为我写一篇关于太空探索的文章。"\n"B：好的，请问…思路吗？"<cont>\n
"A：请写一篇介绍人类太空探索历程的文章…"\n"B：好的，以下是…"<eos>\n
```

⇒ **终止符在闭合引号之后、换行之前，落在回答那一行上**；提问行不含终止符。
于是 `eos_line` 规则在**多轮块里也逐轮命中**，不会只留最后一句。
**掩码臂的前提成立**，实验可以照原判据读。

★ 顺带一个交叉验证：终止符 790,914 个 ≈ 回答行数；回答行平均 ~76 token
⇒ 0.5488%+0.1436% 的终止符密度**恰好**支撑 `mask_density_probe` 量到的
**53.3% 有效 token**（同源两个独立口径自洽）。

复现：
```bash
.venv/bin/python - <<'PY'
import numpy as np
a=np.memmap('data/chinese/train_char_v3_dlg.bin',dtype=np.uint16,mode='r')
n=a.shape[0]; print('total',n)
for k,i in (('<eos>',128),('<cont>',130),('<resp>',140),('<topic>',141)):
    v=int((a==i).sum()); print(f'{k:8s} {v:10,} ({100*v/n:.4f}%)')
PY
```

**纪律提炼**：量语料前先问「**这个符号是在哪一层加进去的**」——
`clean_v3/*.txt`（清洗产物）→ `stages/v3_*/*.txt`（切阶段）→ `*.bin`（tokenize + **标注**）
是三层，同一件事在三层的答案可以完全不同。

## 3. ★★ 身份污染在最大的那个源里 —— 是真的，但**比我先前说的小得多**

> ★★★ **本节 2026-09-17 自我更正过一次，请读完整节。**
> 我 2026-09-16 夜里的原话是「身份污染**集中在**最大的那个源 ⇒ 人格段 900 步打不过是**必然**」。
> **那个论断是从文件开头几段 + 出现次数（没有分母）推出来的 —— 正是 §5.11 禁止的做法。**
> 补量分母后（见下表）：**自称 OpenAI/ChatGPT 的只占该源 3.4% 的字符**（≈`v3_dlg` 的 2%）。
> ⇒ 「打不过是必然」这句**已作废**；真正的解释更可能是**步数太少**（900 步），
> 而不是语料里存在压倒性的反向陈述。

`sharegpt_zh_38k.txt` 是 v3_dlg 里**最大的源**（143.7 MB），它里面确实有大量身份相关对话 ——
**但按字符算，占比不大**（2026-09-17 全量计数，块级分类，分母 = 该源 38,247 块 / 60,727,621 字符）：

| ② 能力否认 / 推诿（不含①） | 2,617（6.8%） | 7,298,739 | **12.0%** |

★ **② 的数不能用**：我把判据收紧成"模型行的**开头**就是（作为AI/语言模型 + 我无法/不能）"后得到
**1,519 块 / 4,650,566 字符 = 7.7%**，但**抽 8 条读原文发现至少 2~3 条是假阳性**：

⇒ 所以 7.7% 只能当**上界**；去假阳性后的真值**本次没有测出来**（见 §6）。
**正确的读法是**：这是一个**真实但中等**的数据缺陷，**不是**"压倒性反向陈述"。

★ 改这个源要重建 bin 并重跑污染率 / 有效 token 验收（§5.10、§9 `build_stages`）。

复现（字符占比，块级分类）：
```bash
.venv/bin/python - <<'PY'
import re
P='data/chinese/stages/v3_dlg/sharegpt_zh_38k.txt'
SELF=re.compile(r'(openai|chatgpt)',re.I); SELFREF=re.compile(r'我(是|由|被|作为|就是)|作为一个|身为一个')
DENY=re.compile(r'我(没有|无法|不能|只是|仅仅|不会)'); LMT=re.compile(r'(语言模型|机器学习模型|人工智能|AI|聊天机器人|程序)')
tot_b=tot_c=c1_b=c1_c=c2_b=c2_c=c3_b=c3_c=0
for block in open(P,encoding='utf-8',errors='replace').read().split('\n\n'):
    if not block.strip(): continue
    tot_b+=1; n=len(block); tot_c+=n
    reps=[l for l in block.split('\n') if l.startswith('模型：')]
    h1=any(SELF.search(l) and SELFREF.search(l) for l in reps)
    h2=any(DENY.search(l) and LMT.search(l) for l in reps)
    h3=any(SELF.search(l) for l in reps)
    if h1: c1_b+=1;c1_c+=n
    elif h2: c2_b+=1;c2_c+=n
    elif h3: c3_b+=1;c3_c+=n
print(f'总 {tot_b} 块 / {tot_c:,} 字符')
for nm,b,c in (('①自称',c1_b,c1_c),('②否认',c2_b,c2_c),('③第三方',c3_b,c3_c)):
    print(f'  {nm} 块 {b} ({100*b/tot_b:.1f}%) 字符 {c:,} ({100*c/tot_c:.1f}%)')
PY

## 4. 与"自主对话"直接相关的第三条：**`<topic>` 一个都没有**

bin 里 `<topic>`(141) = **0**，`<resp>`(140) = **0**。
⇒ 「主动换话题」的机制（`dialogue_stream.py` 的 `new_topic=True`、id 141）
在 **v3_dlg 上完全没有训练信号** —— 它是**为陪聊语料准备的，而陪聊语料没接上它**。
「自主对话」里的**自开话题**这一维，在当前语料下**不可能**被学到，
判据（`eval_multiturn` 的自开轮次率）因此也只会读到语料的先验。

### ★ 4.1 好消息：注入 `<topic>` **不需要改任何代码**（2026-09-17 实测）

我原来**从读代码推断**：`data/chinese/prepare.py:265` 的 `_marker_ids()` 只认
`("<eos>", "<cont>")`，所以往 `.txt` 里写 `<topic>` 会被**逐字符**编码成 7 个 token。
**跑一遍发现这个推断是错的** —— tokenizer 是 WordLevel，直接就把 `<topic>` 认成一个 token：

| 输入 | 裸 `tokenizer.encode` | 走 `_iter_token_pieces`（= `build_stages` 的实际路径） |
|---|---|---|
| `'<topic>'` | `[141]` | `[[141]]` |
| `'<eos>'` | `[128]` | `[[128]]` |
| `'你好<topic>世界'` | `[389, 434, 141, 902, 874]` | 同左（141 在中间，**没被拆**） |

⇒ **`<topic>` 可以直接写进 `stages/v3_dlg/*.txt`，就会变成单个 id 141。**
`_marker_ids` 那条特殊符分割路径**对正确性不是必需的**（它主要服务 `--emit-offsets` 的
字符↔token 对齐）。**注入点就在 `.txt` 层，是最便宜的那种改动。**

复现：
```bash
.venv/bin/python - <<'PY'
import sys; sys.path.insert(0,'data/chinese')
from tokenizers import Tokenizer
from prepare import _marker_ids, _iter_token_pieces
tok = Tokenizer.from_file('data/chinese/char_tokenizer.json')
print('_marker_ids =', _marker_ids(tok))          # {'<eos>':128,'<cont>':130} —— 不含 <topic>
for s in ('<topic>', '<eos>', '你好<topic>世界'):
    print(repr(s), '裸encode=', tok.encode(s).ids, '  走管线=', [p[2] for p in _iter_token_pieces(s, tok)])
PY
```
★ **教训（AGENTS §5.4）**：这一条我"读代码"得到的结论和"跑一遍"得到的**相反**。
凡是要动数据管线的判断，**先跑一个已知答案的输入**再下结论。

### ★★ 4.2 但坏消息在后头：**没有内容可注入**（2026-09-17 实测，同日自我更正）

我 4.1 写完就说"这一维从'不可能学到'变成'**只差标注**'" —— **这句已作废**。
接着量了三件事（全量，`scripts/topic_shift_probe.py` + 一段 ad-hoc 统计）：

**(a) 信号 A（字符 bigram Jaccard 骤降）判死。** 全量 508,624 个候选切换点上：

| 分位 | min | p25 | 中位 | p75 | p90 | max |
|---|---|---|---|---|---|---|
| Jaccard | 0.000 | 0.000 | **0.009** | 0.026 | 0.051 | 1.000 |

30% 恰好为 0；`<0.01` 占 **52.5%**、`<0.02` 占 68.8%、`<0.10` 占 **97.2%**。
⇒ **任何 ≤0.10 的阈值都会把 50%~97% 的轮判成"换话题"** —— 那不是判据，是恒真。
根因：这个语料相邻轮**本来就词面独立**（与 `analysis/corpus_quality_v2.md` 的
"Δ 8-gram 承接 = 0.0000"完全一致 —— 那条**没错**，是我先前把它过度解读成"没有语义依赖"）。
★ 我其实**早该看出来**：`topic_shift_probe.py --selftest` 里那条**真承接**样本
（`对，那颐和园哪个季节去最好？`，上下文是聊北京公园）Jaccard **只有 0.051** ——
一条真承接就已经低于我拍的 0.10。**自我对照报了警，是我没顺着追。**

**(b) 显式线索极其稀疏**：508,624 个候选点里只有 **3,596（0.71%）** 命中
（"换个话题/另外/顺便/还有一个问题"…）。稀疏但精确，可以当作**唯一可用的信号**。

**(c) ★★ 最根本的一条 —— 目标能力在语料里几乎不存在。**
「主动换话题」的正确监督**不在用户侧**（用户换话题只教"识别"），而在**助手侧**。
量助手侧（模型轮总数 **798,828**）：

| 量 | 数 | 占比 |
|---|---:|---:|
| 模型轮**开头**出现开话题线索 | 3,189 | **0.399%** |
| 助手连续两段（自己开了一轮） | **1,489** | <0.2% |

而且**读原文**发现那 3,189 条**大多是"答内连接词"**而不是换话题，例如：

```
模型：压力是生活中不可避免的，可以通过运动、听音乐、和朋友聊天等方式来缓解压力，
      另外定期规律的作息和放下一些不必要的事情也有助于缓解压力。
```

这里的「另外」= **furthermore**，是在**同一个回答内部**列举，**不是开启新话题**。
⇒ 抽读 6 条，约 5 条是这一类。

⇒ **结论：`<topic>` 不是"缺标注"，是"缺数据"。**
注入零成本（§4.1）这件事**仍然成立**，但它只解决了"能不能写进去"，
**没有解决"有没有东西可写"** —— 后者是**数据构造问题**（要造出"助手主动开启新话题"的对话），
比"刷一层标注"贵得多。**我 4.1 那句"只差标注"已在同一节内更正。**

## 5. 三条结论合起来，对"模型为什么不会自主对话"的读法

1. **多轮结构在**（61.8% 的块、81.7% 的字符）⇒ 之前"语料是多轮拼盘、没有承接"的
   印象**需要收窄**：`analysis/corpus_quality_v2.md` 表 7 用的 **8-gram 承接**是
   **表层**代理，而 `用户：继续` → 接着写下一段这种**语义承接本来就不共享 8-gram**。
   ⇒ **"Δ 中位数 0.0000"不能推出"没有语义依赖"**，该文 §9 自己也这么写了。
2. **监督口径没问题**：终止符逐轮覆盖 ⇒ 掩码臂不会丢中间轮。
3. **但有两块硬缺口**：① 语料的**主体**在教"我是 ChatGPT"；
   ② 「自开话题」这一维**零信号**。

⇒ 对"模型怎样才能自主对话"，优先级被这三条改写了：
**先修"训在教的身份"与"零信号的能力"，再谈加步数**。
（加步数会把 §3 的反向身份陈述学得更牢。）
