# dev-notes/77: 神经网络数据库（Neural Database & Memory-Augmented MoE）预研与实现方案

## 一、 核心动机与架构定位

### 1. 为什么叫“神经网络数据库”？
在目前的 Transformer / MoE 架构中，知识的存储和检索存在根本矛盾：
- **稠密权重 / FFN**：知识以“全隐式内积”的形式分散在数十亿参数中，模型想检索一条事实必须前向穿透整层网络。更新一条知识需要全局微调，容易灾难性遗忘。
- **经典 KV Cache**：只能存储短期上下文，随着序列增长，显存按 $O(T)$ 线性膨胀，且缺乏“结构化索引”能力。
- **RAG（外挂向量库）**：外挂外部向量检索（如 Milvus / FAISS），但检索过程脱离了神经网络的反向传播，无法进行端到端可微分训练，语义延迟高。

**神经网络数据库（Neural Database, NDB）的目标**：
构建一个**完全可微分、常数显存、具备百倍容量扩展力**的神经键值存储引擎，直接内嵌在 Transformer 层间，实现：
$$\text{Output} = \text{NeuralDB.query}(\mathbf{x}) = \sum_{i \in \text{Top-}K} \alpha_i \cdot \mathbf{V}_i$$
其中键查找通过高维空间哈希 / 积量化（Product Key）在微秒级完成，值向量 $\mathbf{V}$ 可以容纳数十万条高密度事实。

## 二、 核心技术路线设计

### 路线 A：端到端可微分的 Product-Key Memory (PKM / Large Memory Layer)
*源于 Facebook AI Research / DeepSeek-V3 稀疏激活哲学。*
- **结构设计**：
  - 将 Key 拆分为两个子空间：$\mathbf{k}_1, \mathbf{k}_2 \in \mathbb{R}^{d/2}$。
  - 拥有两个子码本 $C_1, C_2$，每个包含 $\sqrt{M}$ 个子键（例如各 512 个，笛卡尔积形成 $512 \times 512 = 262,144$ 个虚拟记忆槽位）。
  - 对输入查询 $q = [q_1, q_2]$ 分别做 Top-$K$ 最近邻搜索，两两组合出全局最优的 $K$ 个记忆条目。
- **优势**：
  - **$O(\sqrt{M})$ 计算复杂度**：检索 26 万个记忆条目只需做 $2 \times 512 = 1024$ 次点积！
  - 纯可微分，可直接作为 FFN 层的替代或增强分支。

### 路线 B：Titans 启发式“惊喜度”可塑神经记忆 (Dynamic Neural Memory with Surprise)
*源于 Google 2024.12 Titans 论文。*
- **结构设计**：
  - 状态矩阵不再是静态的参数，而是一个随着前向传播动态演进的循环权重 $M_t \in \mathbb{R}^{d \times d}$。
  - **Surprise-guided Writing（惊喜度写入律）**：
    $$\mathcal{S}_t = \| \mathbf{x}_t - \text{Predict}(\mathbf{x}_t \mid M_{t-1}) \|^2$$
    若当前 token 预测难度高（惊喜度大，如“爱因斯坦 1879年 出生于乌尔姆”），则增大动量写入率 $\eta_t$；若是“你好”、“正在为您查询”等低信息量套话，则 $\eta_t \to 0$，拒绝写入，天然抗套话污染。

## 三、 nanoSeek 落地选型：极轻量 Product-Key Neural Database (PK-NDB)

针对当前 8GB AMD ROCm 硬件环境，优先落地 **Product-Key Neural Database (PK-NDB)**：
1. **轻量即插即用**：作为一个可选模块 `model/neural_db.py`，与当前 MLA / MoE 完全解耦；
2. **零显存负担**：只在第 6、第 12 层（中深层语义区）挂载，提供 65,536 个记忆槽位（约 16M 参数），由于稀疏激活，每个 token 仅激活 32 个槽位，算力增加 < 3%；
3. **支持动态热拔插与静态持久化**：槽位可以像数据库一样导出、增量微调（LoRA 化记忆写入）。

## 四、 代码实现草案 (model/neural_db.py)

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class ProductKeyNeuralDB(nn.Module):
    """
    Product-Key 神经网络数据库 (PK-NDB)
    提供 O(sqrt(M)) 复杂度的海量稠密知识槽位寻址。
    
    参数:
      n_embd: 模型隐藏维度 (如 512)
      sub_keys: 每个子码本大小 (如 256 -> 笛卡尔积总槽位 = 256*256 = 65,536)
      top_k: 每个 query 检索的最相关槽位数量 (默认 16 或 32)
    """
    def __init__(self, config, sub_keys=256, top_k=32):
        super().__init__()
        self.n_embd = config.n_embd
        self.half_dim = config.n_embd // 2
        self.sub_keys = sub_keys
        self.top_k = top_k
        self.total_slots = sub_keys * sub_keys
        
        # Query 投射层 + BatchNorm 稳定检索点积分布
        self.q_proj = nn.Linear(config.n_embd, config.n_embd, bias=False)
        self.q_norm = nn.LayerNorm(config.n_embd)
        
        # 两个子空间键码本: (sub_keys, half_dim)
        self.keys1 = nn.Parameter(torch.randn(sub_keys, self.half_dim) * 0.02)
        self.keys2 = nn.Parameter(torch.randn(sub_keys, self.half_dim) * 0.02)
        
        # 实际存储知识的值矩阵 (Values / Database records): (total_slots, n_embd)
        self.values = nn.Embedding(self.total_slots, config.n_embd)
        
        # 输出门控融合 (Output Gate)
        self.out_gate = nn.Linear(config.n_embd, config.n_embd, bias=False)

    def forward(self, x):
        # x: (B, T, C)
        B, T, C = x.shape
        x_flat = x.view(-1, C)
        
        # 1. 计算 Query 并切分子空间
        q = self.q_norm(self.q_proj(x_flat))
        q1, q2 = q[:, :self.half_dim], q[:, self.half_dim:] # 各自 (N, half_dim)
        
        # 2. 子空间点积打分 (N, sub_keys)
        scores1 = torch.matmul(q1, self.keys1.t())
        scores2 = torch.matmul(q2, self.keys2.t())
        
        # 3. 各子空间取 Top-K' (为组合出总 Top-K，取 sqrt 级别候选)
        k_sub = min(self.top_k, self.sub_keys)
        top1_scores, top1_idx = scores1.topk(k_sub, dim=-1) # (N, k_sub)
        top2_scores, top2_idx = scores2.topk(k_sub, dim=-1)
        
        # 4. 笛卡尔积组合出全局得分 (N, k_sub, k_sub)
        cart_scores = top1_scores.unsqueeze(-1) + top2_scores.unsqueeze(-2)
        cart_scores = cart_scores.view(-1, k_sub * k_sub)
        
        # 5. 全局重排序选出最终的 Top-K
        final_scores, final_indices_2d = cart_scores.topk(self.top_k, dim=-1)
        weights = F.softmax(final_scores, dim=-1) # (N, top_k)
        
        # 还原在总槽位 (sub_keys * sub_keys) 中的全局一维索引
        i1 = final_indices_2d // k_sub
        i2 = final_indices_2d % k_sub
        global_idx = top1_idx.gather(1, i1) * self.sub_keys + top2_idx.gather(1, i2)
        
        # 6. 查表读出值向量并加权聚合 (N, top_k, C) -> (N, C)
        retrieved_values = self.values(global_idx)
        db_output = (retrieved_values * weights.unsqueeze(-1)).sum(dim=1)
        
        # 7. 门控残差注入
        gate = torch.sigmoid(self.out_gate(x_flat))
        out = gate * db_output
        return out.view(B, T, C)
```
