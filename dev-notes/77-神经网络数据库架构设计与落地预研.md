# dev-notes/77: 神经网络数据库（Neural Database & Memory-Augmented MoE）预研与实现方案

## 一、 核心动机与架构定位

Transformer / MoE 中知识存储与检索存在根本矛盾：
- **稠密权重 / FFN**：知识以“全隐式内积”分散在数十亿参数中，检索一条事实必须前向穿透整层；更新需全局微调，易灾难性遗忘。
- **经典 KV Cache**：仅存短期上下文，显存按 $O(T)$ 线性膨胀，缺乏结构化索引。
- **RAG（外挂向量库）**：检索脱离神经网络反向传播，无法端到端可微分训练，语义延迟高。

**NDB 目标**：完全可微分、常数显存、具备百倍容量扩展力的神经键值存储引擎，直接内嵌 Transformer 层间：
$$\text{Output} = \text{NeuralDB.query}(\mathbf{x}) = \sum_{i \in \text{Top-}K} \alpha_i \cdot \mathbf{V}_i$$
键查找通过高维空间哈希 / 积量化（Product Key）微秒级完成，值向量 $\mathbf{V}$ 可容纳数十万条高密度事实。

## 二、 核心技术路线设计

### 路线 A：端到端可微分的 Product-Key Memory (PKM / Large Memory Layer)
*源于 Facebook AI Research / DeepSeek-V3 稀疏激活哲学。*
- Key 拆为两个子空间 $\mathbf{k}_1, \mathbf{k}_2 \in \mathbb{R}^{d/2}$；两个子码本 $C_1, C_2$ 各含 $\sqrt{M}$ 个子键（如各 512，笛卡尔积 $512 \times 512 = 262{,}144$ 个虚拟记忆槽位）。
- 对查询 $q = [q_1, q_2]$ 分别做 Top-$K$ 最近邻，两两组合出全局最优 $K$ 条记忆。
- 优势：**$O(\sqrt{M})$ 计算复杂度**——检索 26 万条只需 $2 \times 512 = 1024$ 次点积；纯可微分，可作 FFN 替代或增强分支。

### 路线 B：Titans 启发式“惊喜度”可塑神经记忆
*源于 Google 2024.12 Titans 论文。*
- 状态矩阵是随前向动态演进的循环权重 $M_t \in \mathbb{R}^{d \times d}$。
- **Surprise-guided Writing**：$\mathcal{S}_t = \| \mathbf{x}_t - \text{Predict}(\mathbf{x}_t \mid M_{t-1}) \|^2$；惊喜度大（如“爱因斯坦 1879年 出生于乌尔姆”）则增大动量写入率 $\eta_t$，低信息量套话则 $\eta_t \to 0$ 拒写，天然抗套话污染。

## 三、 nanoSeek 落地选型：极轻量 Product-Key Neural Database (PK-NDB)

针对当前 8GB AMD ROCm 硬件环境，优先落地 **PK-NDB**：
1. **轻量即插即用**：可选模块 `model/neural_db.py`，与当前 MLA / MoE 完全解耦；
2. **零显存负担**：只挂第 6、第 12 层（中深层语义区），提供 65,536 个记忆槽位（约 16M 参数）；稀疏激活每 token 仅激活 32 个槽位，算力增加 < 3%；
3. **支持动态热拔插与静态持久化**：槽位可像数据库导出、增量微调（LoRA 化记忆写入）。

## 四、 代码实现草案 (model/neural_db.py)

关键签名：`class ProductKeyNeuralDB(nn.Module)`，`__init__(config, sub_keys=256, top_k=32)`（总槽位 = 256×256 = 65,536）；`forward(x)`：q_proj/LayerNorm → 双子空间点积打分 → 各取 Top-K' → 笛卡尔积组合 → 全局重排 Top-K + softmax → 查 values 加权聚合 → sigmoid 门控残差注入。
