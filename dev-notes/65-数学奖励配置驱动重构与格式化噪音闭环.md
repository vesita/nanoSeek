# 65-数学奖励配置驱动重构与格式化噪音闭环

日期 2026-09-03（接 64）。涉及 `reward/*`/`grpo_char.py`/`test_arith_reward.py`

## 动机
旧提示词硬编码 6 条在 `grpo_char.py`、运算符识别散在 `rules.py` 两正则，加写法要改两处 → 提示词用 `加上`、奖励不认 → 答对也拿不到分（v3/v4 数学命中恒 0 的部分原因）。目标（用户思路）：**配置生成基础规则 + 代码加格式化噪音**，且**提示词每种写法奖励一定认得出**（生成/识别共用配置）。

## 方案
- `arith_rules.toml`：语义层——数字范围（0~100，**结果也须 ≤100**）、运算表面写法（ASCII/全角符号、中文词）、问句模板。
- `arith_gen.py`：`gen_prompts(count, seed)` 随机挑写法与模板生成噪音提示词池；keywords 含作答短语驱动 r_semantic；`extract_arith(prompt)` 用**同一配置**建识别正则，返回 `(a, op, b, result)`，签名兼容 `rules.extract_arith`；`loose_chinese_digit`+`chinese_to_int` 识别中文数字。
- `engine.py`：识别改走 `arith_gen.extract_arith`；`arith_correct` 改用 `extract_answer_number`——**优先取"等于/答案/得/="后数字**（阿拉伯/中文），再退算式尾部、兜底首数字。修复 bug：`3加4等于7` 正确复述被旧逻辑抓首数字 3 判错 -1.2（旧 keywords 竟把它列为期望）。
- `grpo_char.py`：`ARITH_PROMPTS = arith_gen.gen_prompts(30, seed)` 替代硬编码；数学题独立成池，`--arith_ratio` 现真正控制频率；命中统计同用 `extract_answer_number`。

## 验证
`test_arith_reward.py` 全绿：
- 40 条配置提示词每条都能识别（闭环），答对 +2.5 / 答错 -1.2
- 中文数字答案、全角符号、中文变体全覆盖；复述式作答判对/答错判负——14 例全过
- 修正：乘法结果超 100（如 66×46=3036）不再生成（"100 以内"=操作数/结果均不超界）；**平凡题偏置**（`exclude_trivial`）修复前 mul 60%/div 52% 为 ×1/÷1/×0/a÷a，修复后 mul 2.8%/div 0%（含 0、乘除含 1、a÷a 排除）
- 22 步冒烟（ratio=0.8）通过
