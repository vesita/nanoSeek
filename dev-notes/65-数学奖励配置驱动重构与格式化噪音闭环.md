# 65-数学奖励配置驱动重构与格式化噪音闭环

日期 2026-09-03（接 64）
涉及: `training/rl/reward/arith_rules.toml`（新）/ `training/rl/reward/arith_gen.py`（新）/
`training/rl/reward/engine.py` / `training/rl/grpo_char.py` / `dev_scripts/test_arith_reward.py`

## 动机
旧数学提示词硬编码 6 条在 `grpo_char.py`，运算符识别散在 `rules.py` 两个正则里，
加一种写法要改两处（提示词 + 识别），且两者容易不同步 → 提示词用了 `加上`，
奖励却不认 → 答对也拿不到分（v3/v4 数学命中恒 0 的部分原因）。

目标（用户思路）：**配置文件生成基础规则 + 代码添加格式化噪音**，且
**提示词用到的每一种写法，奖励一定认得出**（生成与识别共用同一份配置）。

## 方案
- `arith_rules.toml`：纯语义层 —— 数字范围（0~100，**结果也须 ≤100**）、
  每种运算的表面写法（symbols=ASCII/全角符号，words=中文词）、问句模板。
- `arith_gen.py`：
  - `gen_prompts(count, seed)` → 随机挑运算符写法（`+`/`＋`/`加`/`加上`/`加一加`…）
    与问句模板（"等于几？"/"等于多少？"/"算一下…"…），生成带格式化噪音的提示词池；
    keywords 含完整作答短语（"答案是7"/"等于7"/"7"… + 中文数字版），驱动 r_semantic。
  - `extract_arith(prompt)` → 用**同一份配置**构建识别正则（写法按长度降序交替），
    返回 `(a, op, b, result)`，签名与 `rules.extract_arith` 兼容。
  - `loose_chinese_digit(reply)` + `chinese_to_int`：识别"答案是七"这类中文数字答案。
- `engine.py`：算式识别改走 `arith_gen.extract_arith`；`arith_correct` 改用
  `extract_answer_number`——**优先取"等于/答案/得/="标记后的数字**（阿拉伯或中文数字），
  再退回算式尾部数字、最后兜底首数字。修复实测 bug：`3加4等于7` 这类"复述题目的
  正确作答"旧逻辑抓到首数字 3 判错 -1.2（旧 keywords 甚至把这种形式列为期望作答，
  奖励却在惩罚它）。
- `grpo_char.py`：`ARITH_PROMPTS = arith_gen.gen_prompts(30, seed)` 替代硬编码；
  数学题独立成池，`--arith_ratio`（此前定义了未生效）现在真正控制出现频率；
  数学命中统计与奖励引擎同用 `extract_answer_number`。

## 验证
`dev_scripts/test_arith_reward.py` 端到端全绿：
- 40 条配置生成的提示词，每条都能被奖励识别（闭环），答对 +2.5 / 答错 -1.2
- 中文数字答案（七/二十四/十）判对；全角符号（×/＋/－）、中文变体（加上/减去/乘上/加一加）
  全覆盖
- 复述题目式作答（3加4等于7 / 我算出来是3加4等于7 / 3加4，答案是7）判对，
  答错（等于8/答案是5/等于9）判负 —— 14 例全过
- 修正：乘法结果超 100（如 66×46=3036）不再生成（"100 以内"= 操作数与结果都不超界）
- 修正：**平凡题偏置**（`exclude_trivial` 开关）—— 实测修复前 mul 60%/div 52% 是
  `×1`/`÷1`/`×0`/`a÷a` 这类平凡题（模型靠回声/模式匹配蒙答案），修复后
  mul 2.8%/div 0%（操作数含 0、乘除出现 1、a÷a 均排除）
- 22 步 arith 高频冒烟（ratio=0.8）通过，日志数学命中路径无崩溃

## 下一步候选
