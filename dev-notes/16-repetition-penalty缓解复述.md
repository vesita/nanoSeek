# 解码重复惩罚（--repeat-penalty）：欠训练复述的即时缓解

> 背景：dev-notes/14 的候选方向里列了"解码时重复惩罚"，本次落地。欠训练模型反复输出"模型：""用户："结构标签 + token 级复读（"先先先"），用户问"要不要加惩罚、能不能上 RL"——惩罚要，但只是治标；RL 不是现在。2026-08-12。

## 现象

采样时模型循环输出对话骨架标签：

```
模型：对。
模型：听起来最扎过不少…
用户：最近有没有哪个小细节…
```

以及 token 级复读：`先把这会儿先先咱先先有感觉`。

## 根因

- 模型**学会了对话骨架、内容没学会**（欠训练 = 重复坍缩，dev-notes/06 同款机制）。训练数据满是"用户：\n模型："结构，模型自回归时陷在骨架循环里出不来。
- 解码端低温度/贪心采样天然偏好高概率 token，已出现的词概率本就高，越滚越高（自增强）。

## 修复

Rust 采样端加 `--repeat-penalty`（`model.rs` 的 `sample()`，CTRL 标准做法）：

```rust
if repeat_penalty > 1.0 {
    let p = repeat_penalty as f32;
    for &t in seen {          // seen = 当前上下文所有 token
        let l = &mut logits[t as usize];
        if *l >= 0.0 { *l /= p; } else { *l *= p; }   // 正除负乘，都往低压
    }
}
```

- 同一个 token 出现几次就压几次（越频繁压得越狠）。
- 顺序：温度 → 惩罚 → top-k → softmax → 多项式采样。
- 默认 1.0 = 关闭，零开销；常用 **1.1~1.3**。
- 同一 seed A/B 实证：1.2 消除"先先先"卡壳，1.3 输出明显连贯（`这种低落感…安静地难过。`）。

## 怎么避免

- **这是治标**。压住复述 ≠ 模型变聪明，内容是半成品的问题没变，根因还是欠训练。
- 正确顺序：**先把模型训满**（val 降到 0.5 以下，复述可能自然消失）→ 仍复述再用惩罚当采样旋钮 / 上训练端 unlikelihood loss → 这些过了才谈 RL。
- **RL 的前提是模型先会说人话**：reward model 的奖励是"这句人话好不好"，模型连语义内容都没有时奖励是噪声，垃圾进垃圾出。
- 只改了采样（`sample()`），`forward()` 未动——`compare_logits.py` 对拍仍通过（max 误差 0.00732），部署守门员没破。
