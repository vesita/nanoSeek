# 31-多轮对话EOS失效诊断与连续对话框架（2026-08-19）

## 现象（用户报告）
多次输入「你好」后模型不再输出终止符 <eos>。

## 诊断（三层）

### 1. 推理框架 bug（已修）：Rust REPL 丢了 EOS
`stream_print` 在 <eos> 处停止，返回的 new_tokens **不含 <eos>**；REPL 直接
`context.extend(new_tokens)` → 下一轮上下文是「模型：回复用户：」——训练里从
没有过这个转移（训练格式是 `模型：a1\n<eos>\n用户：`）。分布外输入 → 行为崩。
**修复**：REPL 命中 EOS 时把 `<eos>+\n` 补回上下文（判定：生成数 < max_new_tokens）。
chat.py 同步改造为跨轮累积 + 训练格式续接（token 级，新增 generate_ids 的
context_ids 参数）。

### 2. 模型层（真实且健壮）：多轮上下文下 EOS 不可靠
- 干净真实多轮历史（muice 原样对话）+ 新问题 → 跑满 150 token 不吐 EOS；
- 不同输入（非重复你好）第 2 轮同样失败 → 与输入重复无关，多轮本身退化；
- 训练数据确认没问题：train.bin 里每轮回复后都有 `\n<eos>\n`，loss 覆盖所有
  回复与 EOS（mask 检查过）。

### 3. 角色错乱（最意外）：模型自吐「用户：」
给定真实多轮历史，模型回复里**自己生成「用户：」**（自问自答），或直接吐空 EOS
（len=0 放弃）。根因怀疑：D 修复（dev-notes/27）把「用户：」边界标签纳入 loss，
教会了「EOS → 用户：」转移——模型过度泛化，把自己当用户续轮。

## 结论
- 框架层已修（必要但不充分——精确训练格式下第 2 轮仍不吐 EOS）；
- 多轮 EOS 失效 = 内容退化（答不上来 → 话术碎片不终止）+ 角色错乱（自吐用户轮）叠加；
- 用户"缺乏连续对话训练框架"的判断部分成立：训练有 multi_turn 数据 + 每轮 EOS，
  但模型没学会"稳定应答 + 角色分离 + 每轮终止"的组合。

## 训练侧可选方向（待用户决策）
1. **回滚「用户：」unmask**（mask 掉用户边界）——验证自吐「用户：」是否由 D 修复引起；
2. **多轮续写专项训练**——multi_turn 数据单独跑 1500 步，强化"历史 → 回复 → EOS"；
3. 接受单轮能力作为 0.2 交付（多轮作为已知局限记录）。
