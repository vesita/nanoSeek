# 48-字节直入方案（Mamba-Byte 思想：无分词器）

## 目标（用户指示 2026-08-30）
把分词器换成 **Mamba-Byte 式方案**：不经过 BPE 分词，直接在 UTF-8 字节序列上训练。
- 词表 256 字节 + 特殊 token（<eos> 等）→ 无 OOV、无分词错误、**话术 token 固化彻底消失**
  （BPE 把"你先跟我说说"这类话术片段并成 token 是话术顽固的次要根源，dev-notes/29）
- Mamba-Byte 的核心是"字节直入 + 长序列便宜"；我们**保留现有架构**（CSA 块+窗是
  O(T) 线性 + 记忆 O(1) 状态）——正好适配字节级长序列，无需引入 Mamba 层。

## 设计
| 项目 | 值 | 说明 |
|---|---|---|
| 词表 | 256 字节 + <eos> 等 ≈ 260 | UTF-8 字节 id（0-255），嵌入矩阵大幅变小 |
| block_size | 256→768 | 中文每字 3 字节：768 字节 ≈ 256 字（与原有效上下文等价）|
| csa_compress | 16→48 | 块 48 字节 ≈ 16 字（等价映射）|
| csa_window | 64→192 | 滑窗 192 字节 ≈ 64 字 |
| 记忆 | latent 16 保持 | 字节级写入更密，16 维是否够待实验（可 32）|
| 训练 | 序列 ×3 → 时间 ×3 | 1500 步 ~60 分钟（预算风险）→ 先 300 步快速 A/B |

## 工作量拆分
1. **字节 tokenizer**：`inference/scripts/` 或 `model/` 下 byte_tokenizer 模块
   （encode=text→utf8 字节 id；decode=反向，需处理流式输出缓冲 BPE 式分片）
2. **数据侧**：`data/chinese/byte_prepare.py`——把现有 txt 语料转字节序列
   （复用 prepare.py 的 source-ratio/对话抽取逻辑，输出 train_byte.bin/val_byte.bin，
   不碰现有 BPE 管线）
3. **模型侧**：vocab_size=260、block_size=768、CSA 参数放大；train.py 支持
   --dataset 指向 byte 数据（或独立训练配置）
4. **推理侧**：sample_py/chat/eval 换 byte tokenizer（decode 时 UTF-8 容错）
5. **验证**：300 步快速 A/B（字节直入 vs BPE 基线，同数据同预算）→ 若可行 1500 步

## 风险与权衡
- 训练时间 ×3（block 768）→ 300 步 ~12 分钟、1500 步 ~60 分钟（超预算需用户确认）
- 所有旧模型作废（dev-notes/04 换词表教训）
- 字节级模型要重新学"字→词"组合（3M 参数 + 1500 步可能不够学汉字组词）——
  **风险点**：小模型字节直入可能学不动（这正是大模型才敢做 Mamba-Byte 的原因）。
  缓解：csa 块 48 字节（~16 字）让注意力天然"成字"；记忆逐字节写。
- 若 300 步 A/B 显示字节版明显劣 → 放弃，回到 BPE（数据优化已见成效）。

## 1500 步结果：❌ 生成质量差，字节直入在小模型上终止（2026-08-30）
- **val 1.467**（每字节熵，从 5.63 降到 1.47，建模很好）
- **但生成全是生僻字**：采样/贪心都出"嗠弌圱嘄庯"类罕见字 + 重复崩溃（弌弌弌…）
- **根因**：3 个字节头**并行**预测 → 组内字节相关性（组合成常用字）未被建模。
  模型学会"字节统计"（高频字节）而非"字级语义"；BPE 词表自带常用字先验，
  字节直入扔掉先验，3M 参数补不回来（Mamba-Byte 是 8B+ 大模型的玩法）。
- val 低 ≠ 生成好：条件字节预测准 ≠ 采样出合法常用字（并行头组合爆炸）。
- **决策：字节直入终止**（小模型不划算）。代码保留（byte 分支 + 推理适配已入库，
  未来若有大模型/组内自回归改进可续用）。
- 推理适配（代理 5626c7d5）已完成并测试（BPE 路径零改动）；无用武之地，记录备查。

## 300 步 A/B 结果（2026-08-30，同数据串行）
| | 字节直入 | BPE |
|---|---|---|
| val @300 | 2.529（每字节熵）| 6.480（每 token 熵）|
| 均匀基线 | 5.55（log257）| 8.99（log8000）|
| 每字 bits | 2.53×3 ≈ 7.6 | 6.48÷1.1 ≈ 5.4 |
| 耗时 | 391s（MFU 0.35）| 531s（MFU 0.10）|

- ✅ **学得动**：300 步 5.63→2.66（每字节熵 5.55→2.53，仍在降）——聚合层学会了"字节→字"
- ⚠️ 效率低于 BPE（每字 7.6 vs 5.4 bits）：同步数下先学"3字节=1字"摊薄学习
- 意外：本次字节版更快（391 vs 531s，参数少+计算密集 MFU 高；含 compile 波动）
- **配置修正**（2026-08-30，1500 步前）：CSA 参数作用于聚合后 token——768 版 48/192
  = 48/192 字（宽 3 倍，误解）；改为 **block 510（170 聚合 token）+ compress 16 + window 64**
  （与 BPE 等价映射）。聚合窗确认 **3 字节**（汉字整字、标记 9B=3 组对齐；4 字节窗会切碎汉字）。
- **1500 步估算 ~20 分钟**（block 510；768 版 ~30 分钟）
- 验收在对话侧（话术固化是否消失）——推理适配代理进行中（5626c7d5）
