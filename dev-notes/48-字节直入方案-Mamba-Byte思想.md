# 48-字节直入方案（Mamba-Byte 思想：无分词器）

## 目标（用户指示 2026-08-30）
分词器换 Mamba-Byte 式方案：不经 BPE，直接在 UTF-8 字节序列上训练。
- 词表 256 字节 + 特殊 token（<eos> 等）→ 无 OOV、无分词错误、**话术 token 固化彻底消失**（BPE 把"你先跟我说说"并成 token 是话术顽固次要根源，dev-notes/29）
- 保留现有架构（CSA 块+窗 O(T) 线性 + 记忆 O(1) 状态），适配字节级长序列，无需 Mamba 层

## 设计
| 项目 | 值 | 说明 |
|---|---|---|
| 词表 | 256 字节 + <eos> 等 ≈ 260 | UTF-8 字节 id（0-255）|
| block_size | 256→768 | 中文每字 3 字节：768 ≈ 256 字 |
| csa_compress | 16→48 | 块 48 字节 ≈ 16 字 |
| csa_window | 64→192 | 滑窗 192 字节 ≈ 64 字 |
| 记忆 | latent 16 保持 | 字节级写入更密，是否够待实验（可 32）|
| 训练 | 序列 ×3 → 时间 ×3 | 1500 步 ~60 分钟（预算风险）→ 先 300 步 A/B |

## 实施与风险
- 实施：byte tokenizer（encode=text→utf8 id，decode 反向+流式缓冲）、`data/chinese/byte_prepare.py`（复用 prepare.py 的 source-ratio/对话抽取 → train_byte.bin/val_byte.bin，不碰 BPE 管线）、模型侧 vocab_size=260/block_size=768/CSA 放大、推理侧 sample_py/chat/eval 换 tokenizer（decode UTF-8 容错）；先 300 步 A/B（同数据同预算）→ 若可行 1500 步
- 风险：训练时间 ×3（block 768）→ 300 步 ~12 分钟、1500 步 ~60 分钟（超预算需用户确认）；所有旧模型作废（dev-notes/04 换词表教训）
- **风险点**：小模型字节直入可能学不动（Mamba-Byte 是大模型玩法）。缓解：csa 块 48 字节（~16 字）让注意力"成字"；记忆逐字节写；A/B 明显劣 → 放弃回 BPE

## 1500 步结果：❌ 生成质量差，字节直入在小模型上终止（2026-08-30）
- **val 1.467**（每字节熵，5.63 → 1.47，建模很好）；**但生成全是生僻字**：采样/贪心都出"嗠弌圱嘄庯"类罕见字 + 重复崩溃（弌弌弌…）
- **根因**：3 个字节头**并行**预测 → 组内字节相关性（组常用字）未被建模；学会"字节统计"而非"字级语义"；BPE 自带常用字先验，3M 参数补不回（Mamba-Byte 是 8B+ 玩法）。val 低 ≠ 生成好
- **决策：字节直入终止**（小模型不划算）；代码保留（byte 分支 + 推理适配已入库，未来大模型/组内自回归可续用）；推理适配（代理 5626c7d5）已测试（BPE 路径零改动）

## 300 步 A/B 结果（2026-08-30，同数据串行）
| | 字节直入 | BPE |
|---|---|---|
| val @300 | 2.529（每字节熵）| 6.480（每 token 熵）|
| 均匀基线 | 5.55（log257）| 8.99（log8000）|
| 每字 bits | 2.53×3 ≈ 7.6 | 6.48÷1.1 ≈ 5.4 |
| 耗时 | 391s（MFU 0.35）| 531s（MFU 0.10）|

- ✅ **学得动**：300 步 5.63→2.66（每字节熵 5.55→2.53，仍在降）——聚合层学会"字节→字"；⚠️ 效率低于 BPE（每字 7.6 vs 5.4 bits，先学"3字节=1字"摊薄学习）；意外：字节版更快（391 vs 531s，参数少+计算密集 MFU 高；含 compile 波动）
- **配置修正**（1500 步前）：CSA 参数作用于聚合后 token——768 版 48/192 实为 48/192 字（宽 3 倍，误解）；改为 **block 510（170 聚合 token）+ compress 16 + window 64**（与 BPE 等价映射）；聚合窗确认 **3 字节**（汉字整字、标记 9B=3 组对齐；4 字节窗会切碎汉字）；1500 步估算 ~20 分钟（768 版 ~30 分钟）
