# 76-稀疏分区字级词表v3与多源语料扩充实证

## 1. 背景与目标
- **数据缺口**：治理后激活语料仅 ~45.8M tokens，距 100M 模型收敛底线（300M~500M）有 10 倍级缺口；
- **分词器刚性**：v2 三区词表把机制符与汉字紧贴排列，新增机制符（Agent/RL）或低频汉字会导致全局 id 错位。

## 2. 多源语料扩充（数据规模 3.4 倍）
增量 9 源（COIG-CQIA wiki/other/zhihu、CodeExercise-Python-27k、GSM8K、Math/Agent/百科/代码 4 类合成）合计 **161,731 条 / ~226 MB**。
`prepare.py --char-level --source-ratio multi_turn=0.15` 编码：训练样本 **988,948 条**（原 511,310 → +93%）、训练字符 **160.48M**（原 76.5M → +110%）、**训练 token 157.37M**（原 73.77M → **2.13 倍**）；验证 token 7.40M（固定切分，评估可比）。

## 3. 四区稀疏分区词表 v3（改良 v2）
总词表 = **8192 = 2^13**（对齐硬件 GEMM 高效边界）：
- 区1 基础字符 0~127 / 128：换行/空格/ASCII 32-126/全角标点（预留 ~11 位）
- 区2 机制符 128~383 / 256：`<eos>/<unk>/<cont>` + 9 命名符 + 预留（**244 位**）
- 区3 汉字 384~8191 / 7808：词频降序 top 6000 常用字（**1808 位**）

关键机制符 id（固定语义，永不更改）：`<eos>=128 <unk>=129 <cont>=130 <pad>=131 <bos>=132 <sep>=133 <call>=134 <result>=135 <think>=136 <answer>=137 <tool>=138 <search>=139`

稀疏空间价值：机制符扩展零错位（新 `<reward>/<observation>/<plan>` 占区2 的 244 预留位，汉字区 id 不动）；低频字无缝追加到区3 尾部 1808 位，旧 checkpoint 已学汉字 id 稳定；2^13 对齐让嵌入层与 LM Head 享受 GEMM 加速。

## 4. 基础设施同步修复
1. **`eos_token_id` 配置化**：新增 `GPTConfig.eos_token_id`，修复 `is_eos = (idx == 0)` 把换行符误当 `<eos>` 的隐患；`train.py` 从 `char_tokenizer.json` 读真实 `<eos>` id（v3=128）注入 config；
2. `prepare.py` 的 `encode_to_bin` 用动态 `token_to_id` 映射，对 id 迁移天然免疫，无需改动。

## 5. 结论
- 数据规模 45.8M → **157.4M tokens**（3.4 倍），覆盖百科/逻辑/数学 CoT/代码/Agent 五大领域，初步补齐 100M 模型通识与推理底座；
- 分词器升级为四区稀疏分区 v3，8192=2^13 布局预留 **~2063 位稀疏空间**，彻底消除 id 错位风险；
- 架构（82M 参数）与 v3 词表接线验证通过，前向 loss 正常，可随时启动长程预训练。
