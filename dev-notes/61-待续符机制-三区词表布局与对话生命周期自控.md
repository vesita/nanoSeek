# 61-待续符机制：三区词表布局与对话生命周期自控

日期 2026-09-03
状态: 已落地（词表 v2 / 数据标注 / 采样 / RL 规划）
涉及: `data/chinese/train_tokenizer.py` / `prepare.py` / `train.py` / `sample_py.py` / `training/rl`

---

## 1. 动机
过去模型只会吐 `<eos>` 收尾（dev-notes/26, 53 强制 EOS 自吐 100%），但收尾陈述（等用户主导）与反问/追问（期待用户继续）是**两种不同的社交动作**，不该共用一个位置锁死。
- `<eos>` = 本轮说完可停，等用户主导；
- `<cont>`（continue）= 本轮说完但**请对话继续**（递回/追问）。

模型在两符间**自主选择**即掌握"自持对话生命周期"，既提升闲聊自然度，又为 RL 提供可打分的自控维度。

---

## 2. 三区词表布局（用户设计的统一管理方案）
重训字级词表 `build_char_wordlevel`，按语义职责分**三个连续区**：

| 区 | id 范围 | 内容 |
|----|---------|------|
| 区1 基础文本 | 0..116 | 换行/空格/ASCII/全角标点 |
| 区2 机制符（固定16位） | 117..132 | `<eos> <unk> <cont>` + 13 预留 |
| 区3 汉字（词频降序） | 133..4532 | 治理后语料词频降序 top 4400 |

区2：117 `<eos>`（本轮终止）、118 `<unk>`（兜底）、119 `<cont>`（请继续）、120..132 `<res0>`..`<res12>` 预留。未来加 `<pad>/<bos>/<sep>/<turn>/<tool>` 直接占空闲预留位，**id 永不迁移**，已训模型不需重对齐。

为什么三区（vs 乱序）：机制符集中同域、一眼可查；基础字符固定在前 → 大字区域 id 稳定；汉字按词频降序（的/是/一/你/不 id 小），覆盖治理后语料 99.9%+ 汉字。

词表参数：总量 `4533` = 基础 117 + 机制 16 + 汉字 4400；低秩嵌入 `factorized_emb_dim=24`（ALBERT 思想），词表增大对参数几乎无感；用 `train_tokenizer.py --char --hanzi-top 4400` 重建。

---

## 3. 数据标注
`prepare.py` 的 `annotate_replies`（替代旧 `insert_eos_after_replies`）按**语义**标终止符：回复**含疑问标记或递回短语**（？/？/吧/呢/你觉得/你说呢/要不要/对不对…）→ `<cont>`；**收尾陈述** → `<eos>`。SFT 阶段即学会"该续/该停"，为 RL 自控提供监督基础（比纯 RL 探索快得多、稳得多）。

---

## 4. 采样端
`sample_py.generate_ids` 把 `<cont>` 与 `<eos>` 都识别为停止点，但语义不同：`<eos>` → 本轮结束等用户下一句；`<cont>` → 本轮输出到此但标记"模型期待继续"，外层据此判断是否该由模型续一句。

---

## 5. RL 自控奖励（规划，暂未启用）
```
r_control = 该续却收尾 → -w（话头冷场）；该停却追问 → -w（车轱辘/唠叨）；决策正确 → +w
```
并需重构 `r_quiet_eos`（当前"强制必须吐 eos，否则扣分"）为**不强制方向**，否则 `<cont>` 会被误判为"没吐 eos"而扣分。
