## 1. 动机：从「被 eos 锁死」到「自持对话生命周期」

过去模型只会吐 `<eos>` 收尾（dev-notes/26, 53 强制 EOS 自吐 100%）。但真实闲聊里，
模型常常需要 **"说出自己的话，然后把话递回给用户"**——一句收尾性陈述（等用户主导）
和一句反问/追问（期待用户继续）是**两种不同的社交动作**，不该共用一个位置锁死。

**待续符 `<cont>`（continue）** 给模型一个显式的对话控制动作：
- `<eos>`  = 本轮话说完了，可以停，等用户主导；
- `<cont>` = 本轮话说完了，但**请对话继续**（我递回/追问，期待你回应）。

模型学会在两符间**自主选择**，就掌握了"自持对话生命周期"的能力——这既提升闲聊自然
度，又为 RL 提供可打分的自控维度。

## 2. 三区词表布局（用户设计的统一管理方案）

重训字级词表（`build_char_wordlevel`），把词表按语义职责分为**三个连续区**：

```
┌───────────────┬──────────────────────────┬──────────────────────┐
│  区1 基础文本   │  区2 机制符区间(固定16位)  │  区3 汉字(词频降序)    │
│  id 0..116     │  id 117..132             │  id 133..4532        │
│  换行/空格/    │  <eos> <unk> <cont> + 13 │  治理后语料词频降序   │
│  ASCII/全角标点 │  预留(未来扩充)           │  top 4400            │
└───────────────┴──────────────────────────┴──────────────────────┘
```

### 区2：机制符区间 16 位（核心设计）

所有**非 ASCII、非自然语言**的机制符号统一占 16 位预留区间，**集中管理、id 稳定**：

| id | token | 当前用途 |
|----|-------|---------|
| 117 | `<eos>`   | 本轮对话终止（收尾，等用户主导） |
| 118 | `<unk>`   | 未登录字符兜底 |
| 119 | `<cont>`  | **本轮说完，请对话继续（递回/追问）** |
| 120..132 | `<res0>`..`<res12>` | 预留 13 位，未来机制符直接替换**

未来要加 `<pad>/<bos>/<sep>/<turn>/<tool>` 等，直接占用空闲预留位，**id 永不迁移**，
已训模型不需重对齐。这就是"预留 16 位"的价值：`<resN>` 不是死字符，是**占了配额的
未来机制符锚点**。

### 为什么三区（vs 乱序）

1. **机制符集中**：所有控制符号同域，tokenizer/sample 一眼可查，未来 mock 不塞进汉字区。
2. **基础字符固定在前**：ASCII/标点是稳定全集，排在前面 → 大字区域 id 稳定。
3. **汉字按词频降序**：高频字（的/是/一/你/不）id 小，词表覆盖治理后语料 99.9%+ 汉字。

### 词表参数

- 总量 `4533` = 基础字符 117 + 机制符 16 + 汉字 4400
- 低秩嵌入 `factorized_emb_dim=24`（ALBERT 思想），词表增大对参数几乎无感
- 用 `train_tokenizer.py --char --hanzi-top 4400` 重建

## 3. 数据标注：从数据学到「该停该续」

`prepare.py` 的 `annotate_replies`（替代旧 `insert_eos_after_replies`）按**语义**给每条
模型回复标终止符：

- 回复**含疑问标记或递回短语**（？/？/吧/呢/你觉得/你说呢/要不要/对不对…）
  → 标 `<cont>`（说完请继续）
- **收尾陈述** → 标 `<eos>`（说完即可停）

这样模型在 SFT 阶段就从语料学会"什么话说完该续、什么话说完该停"的直觉，为后续 RL
自控提供监督基础（比纯 RL 探索快得多、稳得多）。

---

## 4. 采样端：把 `<cont>` 当「软停止」而非「终结」

`sample_py.generate_ids` 需把 `<cont>` 与 `<eos>` 都识别为停止点，但语义不同：
- `<eos>` → 本轮结束，chat 循环等用户下一句
- `<cont>` → 本轮输出到此，但**标记"模型期待继续"**，外层可据此判断是否该由模型续一句

## 5. RL 自控奖励（规划，暂未启用）

待续符最核心的价值在 RL——把「续/停」变成可打分的决策维度：

```
r_control =
  该续(递回暖场)却收尾(→eos)  → -w   (话头冷场：用户抛话题被硬掐)
  该停(收尾已够)却追问(→cont) → -w   (车轱辘/唠叨)
  决策正确                     → +w
```

并需重构 `r_quiet_eos`（当前"强制必须吐 eos，否则扣分"）为**不强制方向**——否则
`<cont>` 会被现有逻辑误判为"没吐 eos"而扣分。这是后续 RL 阶段的具体工作。
