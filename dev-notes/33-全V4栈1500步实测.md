除了之前的验证要点，试试多轮对话（你好/你是谁/你在哪）"。

## 训练

- 命令：`training/train.py training/config/train_chinese.yaml --max_iters=1500
  --lr_decay_iters=1500 --enable_early_stop=False`（WSD：1200 前恒 1e-3，1200→1500 线性衰减到 1e-4）
- checkpoint 确认全栈激活：Muon(lr_scale 0.2) + aux-free + √softplus(route_scale 2.5) +
  swiglu_clamp 0.5 + mHC + CSA(融合QKV) + QK-Norm + Z-Loss + MTP + Sinks + MoE(共享专家)
- 轨迹：250:4.49 → 500:2.68 → 750:2.35 → 1000:2.17 → 1250:1.90 → 1500:**1.6522**
- 耗时 10.5 min（MFU 0.35-0.38，reb 为 0.58——全栈每步慢 ~40%，Muon NS 迭代为主因）

## 结论

1. **val：全 V4 栈 1500 步更差（1.6522 vs 1.2700）**——与 dev-notes/29 B1（Muon 单独即差）
   一致：Muon 在短预算下收敛慢；但全栈（aux-free+√softplus+WSD 等）把 B1 的 2.2260 补偿回
   1.6522，仍追不上 AdamW 基线的 1.2700。1500 步预算下 AdamW 仍是更优选择；
   **V4 栈的价值在长训练（WSD 全周期）而非 1500 步冒进**。
2. **单轮机制：EOS 10/10 超越 reb（9/10）**，续轮 0/10（不喋喋不休）——机制层保持/微升。
3. **多轮：框架侧（token 级累积 + EOS 保留）工作正常，模型侧第 2/3 轮终止符仍不可靠**
   （44% vs 33% 有改善但远不够）——验证 dev-notes/31 结论"必要不充分"：
   单轮 EOS 学会了，条件化的"多轮后该停"没学会（1500 步/0.59 epoch 训练量不足 +
   语料里长多轮占比有限）。
4. **内容：话术碎片不变**——数据构成天花板与架构/优化器无关（dev-notes/29 决定性结论再次复现）。
