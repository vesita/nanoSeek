# 42-算法分析与基线确立（记忆=项目基线 + GPU推理默认 + 性能优化）

## 一、算法复杂度分析（batch 64 × T 256 × d 80 × 6 层）
| 组件 | 复杂度 | 量级 | 说明 |
|---|---|---|---|
| CSA 块路径 | O(B·T·nb·d·k) | 小 | topk=4 稀疏，不随 T² |
| CSA 滑窗 | O(B·T·w·d) | 中 | w=64 固定窗口 |
| 记忆黑板 | O(B·T·C·nh·l) | 中 | chunk D einsum，线性 T |
| MoE FFN | O(B·T·d²·2) | **最大** | 每 token 过 2/5 专家 |
| 对照全注意力 | O(B·T²·d) | 6.7G/层 | 稀疏化已省 ~70% |

**结论：注意力路径已线性于 T（非 T²），推理已是 O(1) 状态更新/步。**

2. **记忆基线配置 = latent 16 + GLM 数据**（基线最终定 latent 16：1500 步验证
   latent 8 略逊——val 2.9143 vs 2.8311、重复率更高；300 步快速测试的"无差"结论

   正式基线：**out/obs_zh_mem1500glm/best.pt（val 2.8311）**。后续 A/B 对照它。
3. **GPU 默认推理**：build_model_from_checkpoint 默认 CUDA（CPU 推理 24ms/tok 占满 CPU 是

   但解放 CPU）。GPU 推理的 multinomial 随机序列与 CPU 不同 → 评估结果随设备波动（已记录）。

## 四、推理性能优化（sample_py.py，CPU 路径，已验证 2 倍提速）
- ① 推理禁用梯度检查点（profile：414 次/60token 无效 checkpoint 调用）
- ② repeat_penalty 向量化（O(T²) python 循环 → 花式索引）
- ③ stop_on_turn 全量 decode（O(T²)）→ 末尾 16-token 窗口检测
- 验证：同 seed 输出逐 token 一致；CPU 49→24 ms/tok（2.04×）；截断语义不变

## 七、A 组更正：compile 应默认开（2026-08-30 实测）
- **原结论错误**：A 组用 3 步短测得出"compile 无收益（0.74 vs 0.79 s/步）"——
  compile 有 ~1.5 分钟一次性编译开销，摊进 3 步当然"无收益"。
- **20 步长测更正**：compile 开 1.29 it/s vs 关 ~1.0 it/s（快 ~25%）；1500 步训练
  编译开销摊薄后净赚。dev-notes/38 的 mem1500（C=32+compile）1.36 it/s 才是长训稳态。
- **已改回**：train.py compile 默认 True。
- 教训：性能对比至少要 20+ 步避开一次性开销（首步 40s 初始化 + compile 编译）。
