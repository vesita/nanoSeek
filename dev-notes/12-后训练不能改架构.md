# 12 · 后训练不能加新架构参数（--init_from=*.pt 时命令行开关被忽略）

## 现象
想给已训练好的模型后训练开一个新开关（比如 `--use_attn_sink=True`），
命令看着没问题，但训练完采样发现**开关根本没生效**——模型行为没变。

## 根因
`train.py` 的 `_build_model_from_checkpoint()`（line 222）用 **checkpoint 里的 model_args**
构建模型，而不是用命令行参数。逻辑是：

```python
# 架构开关：checkpoint 里有的键，用 checkpoint 的值覆盖命令行
for k in [...架构开关列表...]:
    model_args[k] = checkpoint_model_args.get(k, model_args[k])
```

所以 `--use_attn_sink=True` 传进去，但 checkpoint 里 `use_attn_sink: False` 存在，
被 `.get()` 取出 False，覆盖了命令行。**新增架构参数无法注入旧权重**——这是设计意图：
架构必须和 checkpoint 一致才能 load_state_dict，加参数就加载不上了。

## 修复 / 正确做法
- **想加架构开关（Sinks/mHC/indexer 等）必须从 0 训练**，不能后训练注入。
- 后训练（`--init_from=*.pt`）只适合改**训练参数**（步数、lr、dropout），不改结构。
- 判断开关是否真的生效：检查 checkpoint 里有没有对应参数。
  ```python
  ck = torch.load('out/xxx/best.pt', weights_only=False)['model']
  print([k for k in ck if 'attn_sink' in k])   # 空 = 没开 Sinks
  ```

## 怎么避免
给模型加结构特性前，先确认这个开关**必须从 0 参与训练**才有效（Sinks 就是例子：
后训练 300 步的 Sinks 没生效，从 0 训 1000 步就打破重复）。
