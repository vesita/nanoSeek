# 28-反馈式学习/强化学习可行性方案（2026-08-19 设计稿）

项目约束：2.85M 参数、单 GPU（RTX 5060）、每轮训练 ≤1500 步、无人工偏好数据、
基础模型内容单一（只会心理咨询话术，语料 95% 情感支持）。

## 结论先行

- **可做**，但顺序必须对：先解决数据构成（真正的闲聊语料），再 SFT，最后 RL。
  在"只会心理咨询话术"的基座上做 RL，只会把话术打磨得更流畅，不会带来新技能。
- 项目已有反馈式学习雏形：`training/self_distill.py`（Expert Iteration 轻量版——
  高温度采样 → 规则过滤 → 混入训练，p_distill 预算中性混合）。这是"AI 反馈"
  的最轻实现，已接入 train.py。
- 无人工偏好数据 → **不选 RLHF/PPO**（要 reward model + 大量采样，超预算）；
  **GRPO（R1 式，规则奖励）** 是最匹配的：无需 reward model，奖励可全规则化。

## 方案对比

| 方案 | 需要 | 优点 | 缺点 | 判定 |
|---|---|---|---|---|
| 自蒸馏（已有） | 一个好 checkpoint + 采样脚本 | 零新代码，已接入 | 反馈 = 采样过滤，信号弱 | ✅ 已存在，可复用 |
| **GRPO + 规则奖励** | 采样 G 个回复 + 规则打分 | 无 reward model；R1 验证过的稳定算法；奖励可完全规则化（EOS 命中/rep3/长度/续轮） | 需要写 RL 训练循环（~150 行）；小模型 RL 信号弱 | 🥇 首选 |
| DPO + 规则对 | 偏好对（好/坏回复） | 实现简单（CE 变体） | 规则对 = 规则本身的重复，信息量低 | 🥈 备选 |
| RLHF/PPO | 人工偏好 + reward model | 最标准 | 无人力；reward model 训练 + PPO 远超预算 | ❌ 不选 |
| RLAIF（LLM 当裁判） | 一个强裁判 LLM 的 API | 高质量偏好 | 项目是离线本地训练，无外部 LLM | ⏸ 待定（可手动抽查充当） |

## GRPO 最小方案（首选）

```
1. 固定基座：out/chinese-reb（当前最优，val 1.2700）
2. 采样：每 prompt 采 G=8 个回复（镜像 sample_py 的解码，T=0.9/topk=200/rep=1.2）
   prompt 池：multi_turn 的用户轮 + 你好体检的 6 个标准 prompt（dev-notes 已有）
3. 规则奖励（全可脚本化，无人工）：
   +1.0  命中 <eos>（自终止）
   +0.5  rep3 < 0.02（不重复）
   +0.3  长度在 [20, 100] token（不啰嗦不敷衍）
   +0.5  出现第二轮（续轮，验证 mask 修复是否落地）
   -0.5  中文字符占比 < 0.5（英文乱码惩罚）
4. 组内归一化优势：adv_i = (r_i - mean(r_group)) / std(r_group)
5. 目标：max E[log π(a|s) · adv]（策略梯度）+ KL 惩罚回基座（β=0.05）防崩
6. 预算：≤500 步（远低于 1500 上限），lr 复用 SFT 末段
```

## 为什么现在还不是时候（诚实排序）

1. **数据构成是根因**：多轮源（multi_turn 30M）也是情感支持话术，真实闲聊 <5M。
   RL 前的第一步仍是引入/构造闲聊语料，或把话术模型定位成"情感支持机器人"。
2. **欠训练**：1500 步只覆盖 60% 语料（重平衡后）。RL 在欠训练基座上增益有限。
3. **RL 验证指标**：你好体检的 EOS/rep3/len 已接近满分，RL 可再压的只剩
   "内容多样性"——而那是数据问题，规则奖励测不到。
