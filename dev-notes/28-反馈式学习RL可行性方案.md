# 28-反馈式学习/强化学习可行性方案（2026-08-19 设计稿）

约束：2.85M 参数、单 GPU（RTX 5060）、每轮 ≤1500 步、无人工偏好数据、基础模型只会心理咨询话术（语料 95% 情感支持）。

## 结论先行
- **可做，顺序必须对**：先解决数据构成（闲聊语料）→ SFT → 最后 RL；在只会咨询话术的基座上做 RL 只把话术磨得更流畅，不带来新技能。
- 已有 `training/self_distill.py`（Expert Iteration 轻量版：高温采样 → 规则过滤 → 混入训练，p_distill 预算中性混合），已接入 train.py。
- 无人工偏好 → **不选 RLHF/PPO**（要 reward model + 大量采样，超预算）；**GRPO（R1 式规则奖励）** 最匹配：无 reward model，奖励可全规则化。

## 方案对比
- 自蒸馏（已有）✅ 复用（零新代码；反馈=采样过滤，信号弱）
- **GRPO + 规则奖励** 🥇 首选（无 reward model；R1 稳定；奖励全规则化；需 ~150 行 RL 循环；小模型信号弱）
- DPO + 规则对 🥈 备选（实现简单；规则对=规则重复，信息量低）
- RLHF/PPO ❌ 不选（无人力；reward model + PPO 超预算）
- RLAIF（LLM 裁判）⏸ 待定（离线训练无外部 LLM；可手动抽查充当）

## GRPO 最小方案（首选）
1. 固定基座 `out/chinese-reb`（最优，val 1.2700）。
2. 每 prompt 采 G=8 回复（镜像 sample_py：T=0.9/topk=200/rep=1.2）；prompt 池 = multi_turn 用户轮 + 你好体检 6 标准 prompt。
3. 规则奖励（全脚本化）：+1.0 命中 `<eos>`；+0.5 rep3<0.02；+0.3 长度 ∈[20,100] token；+0.5 出现第二轮（验证 mask 修复）；−0.5 中文字符占比<0.5。
4. 组内归一化优势 adv_i = (r_i − mean(r_group)) / std(r_group)。
5. 目标 max E[log π(a|s)·adv] + KL 回基座（β=0.05）防崩。
6. 预算 ≤500 步（远低于 1500 上限），lr 复用 SFT 末段。

## 为什么现在还不是时候
1. **数据构成是根因**：multi_turn 30M 也是情感支持话术，真实闲聊 <5M；第一步仍是构造闲聊语料，或定位成"情感支持机器人"。
2. **欠训练**：1500 步只覆盖 60% 语料（重平衡后），RL 在欠训练基座上增益有限。
3. **RL 验证指标**：你好体检 EOS/rep3/len 已近满分，可压的只剩"内容多样性"——数据问题，规则奖励测不到。
