# 06 · 欠训练 = 重复坍缩（怎么诊断）

## 现象
模型输出 `悟空悟空悟空…`、`灯下灯下…`、一连串引号或换行。

## 根因
小模型欠训练时，学到的不是"合理的下一个词"，而是两个省事策略：
1. **重复上一个 token**（不确定时的默认答案）
2. **坍缩到高频 token**（新行 `\n`、单引号 `'` 这类语料里最常出现的）

## 诊断三步（都是低成本实测）
```sh
# ① 看 top-10 logits：分布太平 → 没信心；某个少见 token 独高 → 坍缩
./target/release/nanoseek-runtime --print-logits --prompt "$'用户：你好\n模型：'"

# ② 把 top token 解码出来，看是不是 \n / ' 这类无意义 token
uv run python -c "from tokenizers import Tokenizer; t=Tokenizer.from_file('data/chinese/tokenizer.json'); print(repr(t.decode([177])))"   # -> '\n'

# ③ 对照训练数据：统计"模型：后面跟换行"的比例，排除数据格式问题
```
> 本例实证：`模型：` 出现 20 万次，紧跟换行的 **0 次（0.0%）**。
> 数据格式没问题，是模型把高频 token 当成了默认答案。

## 怎么避免
"模型输出垃圾"先分三层排查，别急着改代码：

| 层 | 问题 | 检查 |
|----|------|------|
| 数据 | 格式错 / 语种错 / 有污染 | 采样看原文 + 统计关键模式 |
| 训练 | 欠训练 / 超参崩 | loss 曲线 + tokens/参数（Chinchilla ~20）+ logits 分布 |
| 部署 | 旧模型 / 缺 EOS / prompt 不一致 | 文件时间戳 + 生成循环 + 格式逐字符对比 |

通常最后发现是**训练量**或**容量**问题，而非部署 bug。
