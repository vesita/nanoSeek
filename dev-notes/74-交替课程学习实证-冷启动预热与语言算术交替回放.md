# 74-交替课程学习实证：冷启动预热与语言-算术交替回放的动态平衡与容量约束

## 1. 背景与核心假设
`nano_arith`（485k 参数）上已验证进位电路可快速收敛并对字面噪声不变（Note 70-73）。用户提出假设：
> 能否在 4.5k 字级大词表基础模型（3.39M 参数，含 MoE、KV 记忆、CSA）上先算术冷启动预热、再少量语法训练、随后算术复训——即「300 步算术冷启动 + 28 轮（100 步语言对话 $\leftrightarrow$ 20 步算术回放）」交替推进，在算术能力不强烈下降下逐步学习自然对话？

目标：容量有限（3.39M）+ 词表 4,533 下逻辑回路与自然语言的梯度交替平衡机理。

## 2. 实验设置
- **架构**：标准基础架构（6 层，4 头，80 维，MoE 8 专家 top-2，KV Memory、CSA 压缩滑窗、Attention Sinks、QK-Norm），**3,386,000 (3.39M)** 参数，词表 4,533；权重从 scratch 随机初始化。
- **数据**：自然语言 `data/chinese/train_char.bin`（4,583 万 Token，Assistant Mask）；算术流为带 Scratchpad 进位链（`c`）与 50% 字面扰动的 1~3 位加法。
- **课程**：阶段 0 = 300 步高密度加法（LR 0 → 1e-3 预热）；阶段 1~28 = 28 轮 ×（100 步语言 + 20 步算术回放），累积语言 2,800 步（1 个完整语言 Epoch，4,587 万 Token）、算术回放 560 步；**总步数 3,660**。

## 4. 核心结论
- **语言能力极佳收敛**：语言 Val Loss 5.3889 → **2.9359**，与常规 1-epoch 基线完全一致；已学会中文词汇搭配与对话句型（如 `"我们是的,我们是一个..."`）→ **穿插算术回放完全不损害主干语言模型的表征学习能力与收敛速度**。
- **逻辑能力的"擦除-重写"非对称性**：
  - **词表稀疏与 Grokking 门槛**：`nano_arith`（词表 56）300 步即 Grokking 至 100% EM；大词表中数字与加减号 Embedding 梯度占比极小，300 步仅够"语法格式对齐"（产生 `1c1`、`0c1` 等进位形式），进位因果权重尚未固化。
  - **语言海量梯度的淹没效应**：每轮 100 步语言训练梯度方差极大（覆盖 4,500 万字语料中几千汉字），迅速冲刷尚未固化的加法逻辑。
  - **20 步回放的弹性上限**：仅能将算术从完全失忆拉回局部偶发唤醒（**2.5% EM**），保留数字与加法符号敏感度（如 `45+78=` 输出带 `7c7` 的进位特征序列而非随机文字），但无法全面抗衡 5 倍步数的通用语言擦除。

## 5. 启示与下一步
首次在 nanoSeek 完整架构跑通"预热冷启动 + 交替回放"跨模态课程范式。优化路径：
1. **非对称步数比率调整**：`100 步语言 : 20 步算术` → `50:50`，或改用 **Data Mixing（混合批次：80% 语言 + 20% 算术同步更新）**，消除"先学后擦"的时序颠簸。
2. **参数隔离与 MoE 路由特化**：用内置 8 个 MoE 专家，以特定 Loss 引导 1~2 个 Expert 专司"算术逻辑专家"，避免语言前向更新覆盖算术专家权重。
3. **充分 Grokking 后再接入语言**：Stage 0 延长至 1000~1500 步，待进位回路拓扑固化后再引入温和语言微调。
