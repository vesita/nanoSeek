# 计算图重排：块内子层顺序（attn↔ffn）

## 背景（为什么做）

用户判断**拓扑才是关键**：Sinks 是纯拓扑改变、是唯一实证打破重复的手段（dev-notes/11）；训满反而失效（dev-notes/14）证明天花板在拓扑而非参数量。本实验落地拓扑优化的第一个维度——**块内子层执行顺序**：现有逐块 `attn→ffn`（Pre-LN）布线换成 `ffn→attn`，同一参数量下智能（采样质量）是否不同。

## 改动（Python-only，零参数）

- `model/model.py`：`GPTConfig` 加 `block_order: str = "attn_ffn"`；`Block.forward` 与 `_mhc_forward` 按 `block_order` 调换子层顺序。`_mhc_forward` 抽了个 `_mhc_sublayer(x, is_attn)` 小方法，与 Rust 端 `mhc_sublayer` 对称。
- `training/train.py`：`block_order` 全局变量 + `model_args` + checkpoint 兜底（旧 ckpt 无此键 → 默认 `attn_ffn`）。
- 配置：`train_chinese.yaml` 显式 `block_order: attn_ffn`；新建 `train_chinese_fa.yaml`（fa 臂，`ffn_attn` + `out_dir: out/chinese-data2-fa`）。
- **Rust 端不动**（本次已还原）：实验性改动只停留 Python 层，否则对拍 + 双平台打包测试成本太高。

关键约束：**norm 与子层绑定不可拆**——attn 永远用 `ln_1`，mlp 永远用 `ln_2`，只调换两段的前后位置。权重名零变化。

## 验证（已跑）

- 参数量严格相等：af/fa 都是 **2,868,986**；state_dict 键名零差异。
- 标准路径 + mHC 路径两种顺序各训几步，forward/backward 正常；fa 与 af 的 val 损失最后一位不同 → 确认换了计算路径、不是空转。
- **对拍守门员回归通过**：默认 `attn_ffn` 下 compare_logits max 误差 0.00732 < 0.01、top-5 一致 → mHC 重构数值逐位对齐，现网部署没被破坏。
- `smoke_test.py` 通过（新增 `ffn_attn`、`ffn_attn+mHC` 用例）。

## 怎么跑 A/B（用户跑，seed 固定 1337，唯一变量 = block_order）

```sh
# af 臂（对照，用 --out_dir 避开覆盖当前 best 模型）
uv run python training/train.py training/config/train_chinese.yaml --out_dir=out/chinese-data2-af
# fa 臂（实验）
uv run python training/train.py training/config/train_chinese_fa.yaml
```

同步数（建议先 2000 对齐 chinese-data2 参照），各跑 3 个 prompt 采样目测对比，配 `--repeat-penalty 1.2` 压噪音。

## 实验结果（2026-08-12，串行各 1500 步，seed 1337）

val loss 对比（越低越好）：

| step | af (attn_ffn) | fa (ffn_attn) |
|------|--------------|---------------|
| 250 | 4.6243 | 4.6515 |
| 500 | 2.9083 | **2.8956** |
| 750 | 2.4640 | 2.5135 |
| 1000 | 1.9671 | 2.0356 |
| 1250 | 1.4509 | 1.4924 |
| 1500 | **1.0867** | **1.2543** |

采样目测（2 个对话 prompt × 双臂，seed 相同）：af 保持用户/模型交替的对话框架、有追问；fa 模型段过密、内容更碎更跳。两个判据一致。

**结论：默认 `attn_ffn`（Pre-LN 逐块 attn→ffn）胜出，ffn_attn 无优势且略差。** 这是有价值的负结果——块内子层顺序不是"拓扑是关键"的关键维度。把搜索引向跨块结构 / 记忆槽（或需 flat-list 重构的稠密注意力 AFA/AAFF）。fa 臂 checkpoint 不可部署 Rust，实验到此为止，Rust 端维持 attn_ffn 无需任何改动。

## 判据与诚实标注

- **判据以采样质量（智能）为准**，loss 只是必要条件——val 可能相同但采样差异才是信号。
- fa 臂 checkpoint **不可部署到 Rust**（Rust 只做 attn_ffn）。若 fa 采样胜出，再补 Rust 支持作为后续阶段。
- 若 af/fa 结果几乎一样 → 块内顺序不是拓扑的关键维度，把搜索引向别处（跨块结构/记忆槽），这本身是有价值的负结果。
- 稠密注意力（AFA/AAFF）需 flat-list 重构 + 权重 remap，破坏兼容，另起实验。
