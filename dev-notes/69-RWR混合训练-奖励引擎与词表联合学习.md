# 69-RWR/GRPO 混合训练: 奖励引擎与词表联合学习 (用户提案验证)

日期 2026-09-04（接 68）

## 提案
用户: "奖励引擎可以和词表混合着学" —— 不再两阶段 (SFT → RL), 把奖励信号混进基座训练目标, 每步同时优化语料 next-token CE 与奖励引擎打分的采样候选加权信号。

## 实现
`rwr_mixed_char.py` (`--rl_mode grpo|rwr`):
`loss = λ_ce·CE(语料, assistant-mask) + λ_rl·RL项 + β_kl·KL(→基座) + λ_q·EOS静默`
复用 sampler/RewardEngine/grpo_char 提示词池与语感门控；对照同起点 cont_v1_1epoch + 300 步，对标 rl_coh_dialog。

## 发现 1: RWR 在 2.7M 上必塌 (v1/v2/v3 三次实测)
- 三种配置 (纯语料CE/全token、加KL兜底、加Anti-Dwarf+winsorize+门控修正) 全部在 step 30~200 塌向空回复: 均长→0~2、乱码 53%、多样性 62%，无法恢复。
- 根因 (结构性): **RWR 权重恒正 (softmax), 只"模仿"高分、从不"压制"低分候选**; "次优壳"(`"`、二字残句) 拿到相对高权重即被模仿 → 自我强化 → 塌缩。GRPO 组相对优势**可正可负**, 负优势主动压低坏输出 (rl_coh_dialog 300 步健康, 均长 8-20)。
- 踩坑 (均已修): ① 语料 CE 必须 assistant-mask (全 token CE 让模型学"预测用户轮次", loss 5.0 vs masked 2.5); ② 退化时 KL/EOS 静默必须全程在场, 不能随 RL 权重清零; ③ masked CE + MTP 辅助 loss 在有效 token <~32 时 targets 全 -100 → 0/0=NaN → 需 min_valid 过滤重采样; ④ 退化门控"组最佳"须用 argmax 奖励候选长度, 非组内最短 (v2 用 min 几乎每步误判 → RWR 清零 → 塌)。

## 发现 2 + v4 全量 (300 步, dialog_quality 两轮取中)
- 换 GRPO 后冒烟 40 步健康: 均长 9~21.5 与 rl_coh_dialog 一致, 退化步 2/40, CE 下降。
- v4 vs 基座 vs 纯GRPO300: 乱码 9%/5~7%/**2~3%**; 均长 11.5/19~20.4/26.1~26.8; 温和确认腔 0/8/2/8/1~2/8; 退化步 -/~稀疏/~6; 多样性均 100%。
- 主观: 基座碎片 → 纯GRPO 套话通顺 → v4 更自然、碎片最少。

## 结论
1. 提案成立, 机制必须是 **GRPO 组相对优势, 不是 RWR** (RWR 三次全塌均长→0; GRPO 负优势压制坏输出 + CE 同场 300 步健康)。
2. 语料 CE 混合可复现增益: 乱码 2-3% < 5-7%, 均长更稳 (26+ vs 19-20); 词表在场 = 更强语言锚。
3. 口径: 是"更稳的 GRPO"而非"更聪明" —— 收益在语言稳定性, 不在理解/算术 (容量天花板不变, 见 68)。
4. 产物: `out/rl_mixed_v4/best.pt` (新最佳对话模型, 建议后续部署用它)。
