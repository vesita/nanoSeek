# 59-强化训练奖励作弊根因与反乱码门控落地

日期 2026-09-03
涉及: `training/rl/multi_reward.py` / `grpo_char.py` / `run_curriculum.py`

## 现象
v6/v7 12 阶段课程中, GRPO 把**纯乱码 token 沙拉**判成 raw_s≈+4 / exp_R≈+13 当正样本强化。全组退化保护(`组最高分<0`)只在最佳候选 raw<0 时拦, 乱码沙拉 raw>0 漏过 → 组内相对优势把乱码自增强 (EOS 坍缩路)。

## 根因
7 维奖励全是**表面特征** (长度/熵/无标签/EOS/暖词/关键字/n-gram 语义), 不感知"是否像人话"; 随机汉字串能同时满足全部条件 (长度 8-65、3-gram 高熵、无「用户/模型」标签、吐 EOS)。

## 校准探测 (.probe2.py, ref=out/eos_fix_1epoch 17200步基座)
mean-logp(回复区): 基座自采样 -7.8 (std 1.87) / v6/v7 乱码沙拉 -13.9 / 人工流畅中文 -12.2。
1. 基座似然度能干净区分「乱码 vs 模型语感」→ 做**门控**, 不做奖励。
2. **基座自采样本身就不通顺** (-7.8 vs -12.2), 符合 dev-notes C「质量天花板 = 步数预算 + 语料构成」; 用似然度奖励流畅会**反向惩罚**。

## 修复
- `multi_reward.py`: 新增 `r_coherence` + `w_coherence=2.0`, `evaluate_reply` 新 `coherence` 入参 (None=不启用)。
- `grpo_char.py`: **anti-salad 门控** `COH_THETA=-7.8 / COH_SIGMA=2.0 / GATE=2.2σ`, 最佳候选基座 mean-logp < 阈值 → 整组降级退化, 只做 KL 拉回基座+EOS 静默; `--ref_base` 固定原始 SFT 基座防漂移。
- `run_curriculum.py`: grpo 阶段追加 `--ref_base initial_ckpt`。

## 验证
单测: 空回复 -3.5(塑形 -9.3), 乱码沙拉 R=-0.63, 高质量回复 2.39; 5 步冒烟无崩溃。Stage 1 (100轮) 门控放行 (avg_len 46.8 / rep 3% / d1 0.32 / 裸prompt空 0%); EOS 自吐 30% (基座 80%) 需监控。

## 落地与实证 (curriculum_v8, 2026-09-03)
`run_curriculum.py --all --start 2 --out out/curriculum_v8`
Stage2-6: EOS自吐 27/50/33/43/20%, 短语重复 3% 恒定, d1 0.34/0.35/0.33/0.30/**0.26**, 裸prompt空 7/7/13/0/0%; Stage6 d1 跌破 0.3 → ⛔ 退化中断。
1. **门控 + 固定基座锚点有效**: v6/v7"乱码当正样本自增强"路径消失, 5 阶段(500 轮)只出现正常退化组拦截(KL 拉回)。
2. **退化门控在 Stage6 正确工作**: d1 跌破 0.3 中断, **最好的 ckpt 是 stage_05_500**。
3. **质量天花板是 SFT 语料, 不是 RL**: base vs stage5 都仍 broken 语感, 500 轮 RL 未变流畅。
