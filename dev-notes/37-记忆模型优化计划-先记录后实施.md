## 优化方向（按实施顺序）

### A. chunk 并行训练（先做：提速一切后续迭代）
把 256 步顺序递推改成 **4 个 chunk × 64 步并行**（GLA 论文做法）：

```
递推（现状，逐 token）：S_t = r_t ⊙ S_{t-1} + β_t k_t v_tᵀ，o_t = (S_t + persist)·q_t

chunk 并行（C=64）：
  块内 g = log(r)，G = cumsum(g)（每通道，≤0）
  o_i = exp(G_i) ⊙ (S_in·q_i) + exp(G_i) ⊙ Σ_{j≤i} exp(−G_j) ⊙ (β_j k_j)(v_j·q_i)
  块间状态：S_out = exp(G_last) ⊙ S_in + exp(G_last) ⊙ Σ_j exp(−G_j) ⊙ (β_j k_j) v_jᵀ
  因果 mask 用 tril；块间只 4 次顺序步骤/层
```

**数值安全（必须 clamp）**：r→0 时 exp(−G_j) 会溢出。做法：
`G.clamp(min=-30)` → exp(G) ≥ 9e-14（不为 0）、exp(−G) ≤ 1.1e13（不为 inf）
→ 无 inf×0 的 NaN 风险；状态累加保持 fp32。

**预期收益**：顺序步 256/层 → 4/层；torch.compile 可重新启用；
2.2s/步 → ~0.7s/步（3 倍提速）；1500 步 ≈ 20 分钟内。

**验证**：用已训好的记忆模型，chunk 实现 vs 顺序实现输出逐位对齐（rtol 检查）+ smoke_test。

### B. P2：Delta 擦写律（方法升级，A 之后再议）
```
S ← f ⊙ S + β(v − S·k) kᵀ    先擦冲突联想再写入
```

## 实施记录（A 落地 + 两个计划外发现）

### A ✅ 已落地（_kv_memory_forward chunk 并行版）
- 等价性验证：与顺序版输出相对差 **3.688e-07**。验证抓到两个 bug：
  ① 把 cumsum 直接 clamp(min=-30) **破坏位置间相对衰减**（真实模型 r 小、64 步 cumsum 深负）
  → 修正为 **exp(G_i−G_j) 差值矩阵（j>i 先置 −inf 再 exp）**——这是对原计划"必须 clamp"一节的**更正**，
    计划里写 clamp 是为了防溢出，但正确做法是差值形式，指数天然 ≤0 无溢出。
  ② 重写时把检索因子 (v_j·q_i) 弄丢（scores 变死代码）→ `inner = einsum('bijhl,bihj,bjhl->bihl', D, scores, ck)`。
- smoke_test 通过，compile 恢复（test.yaml 13 it/s）。

### ⚠️ 发现 1：C=64 @ batch64 OOM（工程债 → 显存债）
- 现象：1500 步链式训练第一发记忆条崩溃（`torch.OutOfMemoryError`），`| tail` 吞掉了非零退出码，
  基线条照常跑完 —— 链式命令必须保留退出码（教训：`| tail` 后加 `set -o pipefail` 或检查 ${PIPESTATUS[0]}）。
- 根因：chunk 版 D 矩阵（块内衰减 B×C×C×nh×l）要存整图供反向，
  **全序列总量 = B·T·C·nh·l，C=64@B=64 → 1.6GB fp32**（顺序版逐 token 只有小张量所以不炸）。
  compile=true 也一样炸（6.39GB 已分配 + 498MB 请求失败）；`PYTORCH_CUDA_ALLOC_CONF=expandable_segments` 无效。
- 修复：`kv_memory_chunk` 入 config（默认 64），训练用 **C=32**（D 总量降到 800MB）→ 不 OOM。
- **C=32 + compile=true 稳态 1.32 it/s（0.76s/步），与基线同速** —— 计划里"~0.7s/步"预期达成。
  注：compile 对记忆 einsum 路径无额外提速（RDNA2 inductor 对异形 einsum 不友好），但也不拖后腿。
- 决策修正：chunk 不再是固定 64，而是 config 参数；大模型训练用 32，小模型 smoke 保持 64。
