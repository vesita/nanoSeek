## 一、判死实验链（三套独立 + 一组最强证据）

### 实验 1: 纯 RL 数学 warm-start
- v1 (1000步, arith_ratio 0.35): 命中 2.5%→3.8%
- v2 (300步, 奖励修复后 arith_ratio 0.6): 命中 0%（废话被罚但不会算）
- 训练全程 0% 坍缩（反坍缩加固有效）; 对话退化(len<=1 25%)也由 v2 修复到 0%

### 实验 2: SFT 教个位数加法（非 RL）
- 训练 a,b∈1..5 和<10 (24条), 测 a/b>5 泛化(12条)。lr1e-4 bs8 700步。
- loss →0.0019 (拟合极好), 但 train 记忆 ~20%, 泛化 **0%**。
- argmax 解码: 几乎所有输入回同一类数字(1+1→3, 2+2→3, 4+4→6), **不区分算式**。

### 实验 3: credit-assignment 数字位概率分析（最精确）
sft_v3 模型对 "a加b=?" 后下一 token 的概率分布:
```
1+1=2:  P('2')=-1.93  但 P('3')=-0.24(更高!)   top=3,2,4 (各~28-29)
3+4=7:  P('7')=-5.55  但 P('6')=-0.67(更高!)   top=6,4,3
```
→ 模型把概率质量**平均摊在 2-6 所有数字上**, 正确数字只比错误高一丁点甚至更低。
输出数字与输入操作数 (a,b) **完全解耦** —— 它没形成"把注意力指向 a,b 并求和"的表示。

### 实验 4（最强铁证): 全覆盖加法表 81 组合 SFT
- 训练集 = 全部 a,b∈1..9 (含进位, 1+1..9+9, 81组合全在集内, 让模型"背表")。
- loss →0.0058, 但 600 步后 40 抽样记忆仅 **4/40 = 10%**。
- loss 低因答案区"答案是"3固定字+<eos> 高频好预测, 数字位真实预测仍失败。
- **2.7M 连 81 条 (a,b)→s 的记忆表都背不下**（只能抓住少数高频），遑论泛化计算。

## 二、为什么（机制层归因, 收敛）
- 6层×80d×4头 = 2.7M 参数, block 256。要表示 "识别两操作数→求和→转数字 token"
  需要足够容量存"查表/计算"的输入编码条件映射。
- 纯 next-token 目标下, 它学的是**词序分布**; (a,b)→s 是**输入编码的条件变换**,
  该模型没有足够归纳偏置/容量去表达, 尤其在从零(基座只会闲聊)起步时。
- RL 调奖励、加步数都无法绕过: 无"从废话到正确计算"的中间态可学, credit 无法回溯
  到"算出 40+27"这一步(55 token 里数字 token 仅 1-2 个)。
- **已排除**: 奖励地形(v1↔v2)、训练不充分(RL+SFT 都试)、格式/词表(数字token存在)。
