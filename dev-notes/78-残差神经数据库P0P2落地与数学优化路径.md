## 一、框架：外部残差神经数据库（ResidualNeuralDB）

### 1.1 结构（`model/residual_neural_db.py` + `model/product_key_memory.py`）

```
ResidualNeuralDB
 ├─ memory: ProductKeyMemory  (1M 槽, key_dim=128, sub_keys=1024, top_k=16, temperature=0.1)
 │    ├─ keys1/keys2: (1024,64) 双子空间码本   → 笛卡尔积 = 1024² = 1,048,576 槽
 │    └─ values: (1M, key_dim)  记忆内容, 纯 no_grad（requires_grad=False, 零优化器状态）
 ├─ 读路径: q_proj(512→128) → q_norm → memory.retrieve → logits_proj(128→vocab) 或 hidden_proj(128→512)
 ├─ 写路径(高惊讶错题本): k_proj(512→128) → k_norm → memory.write
 ├─ 门控:   read_gate(h) → sigmoid（bias 初始化 -2.0, 即默认注入强度 ~0.11）
 └─ target_enc: nn.Linear(512, key_dim)  压缩目标嵌入为 128 维 value
```

检索复杂度 `O(sub_keys)`（每个 query 只 `2×1024` 次点积），而非 `O(M)`，这是 ProductKey 的核心优势。

### 1.2 两条注入路径

| 路径 | 注入点 | 数学作用 | 脚本 |
|---|---|---|---|
| **logits 层** | 最终 ln_f 输出 h → 检索 → `logits + gate·Δlogits` | 词表概率分布自适应纠偏 | `local/train_residual_db_v3.py` |
| **隐藏层** | `transformer.h[-2]` 输出（倒数第二块）→ 检索 → 加回 2 流 | 修正传播到未来（其后仅 1 attn + mHC + ln_f + head 近线性路径，流形破坏最小） | `local/train_residual_db_hidden.py` |

mHC 块输出为 `(B,T,hc,n_embd)`，隐藏路径注入前先 `mean(dim=2)` 取单流，注入后广播回各流。

### 1.3 核心机制（高惊讶写入）

```python
surprise_mask = cross_entropy(logits, targets, reduction="none") > surprise_threshold  # 默认 3.0
# P2: surprise_mask &= ~isin(targets, {128,129,130,-100})   # <eos>/<unk>/<cont>/mask
val = target_enc(target_emb − pred_emb)                      # P0: 残差（见下）
memory.write(k_surprise, val, weight=clamp((loss−3.0)/2, 0.2, 1.0))
```

## 三、P0 + P2 落地（100 步验证）

### P0（机制升级）：value 从「目标嵌入」改为「残差」
- 旧：`value = target_enc(target_embedding)` —— 存「正确答案长什么样」
- 新：`value = target_enc(target_embedding − base_pred_embedding)` —— 存「模型缺的那块信息」

**数学意义**：DB 从「绝对答案查找表」变成「残差修正器」。基座对时残差≈0（自动不干扰）；基座错时残差大（存的正是缺口）。规避「复制已知状态」。

### P2（噪音过滤）：写库排除无信息目标
`ignorable_ids = {-100, 128, 129, 130}`（生僻字占位 / eos / cont / mask）。
**关键验证**：reserve 生僻字（res_han/res，2064 个词表 token）在训练流占 **0.00%**——它们只是词表空槽、从不参与 encode；真实生僻字全走 `<unk>`(129)（占 1.085%），已被正确挡掉。

### 后果 vs 无改进 run1

| 步 | 无改进 run1（同期） | **P0+P2（本次）** |
|---|---|---|
| 25 | （无 eval） | **−0.0007** ✅ |
| 100 | +0.0005 | +0.0001 |

**早期从「有害」转「帮助」（step25 −0.0007）**，但 100 步内未稳定保持 → 机制改对了，但训练不足。

## 四、数学/算法层面诊断（用真实基座 + 已存库实测）

在对 P0+P2 库做诊断时，捞出 4 个关键量，直接解释了「为何 Δ≈0」：

| 信号 | 实测 | 含义 |
|---|---|---|
| 读取锐度 | top1 权重 **0.59**，熵 **1.24bit**，参与比 **16.1** | 读在 16 槽间**扩散混合**，不 commit 到最强命中 |
| 记忆值流形 | 被混合的 16 值两两余弦 **≈0.0002** | 值仍是**近正交随机向量**，未组织成修正 |
| 写键分布 | 4605 写/步 → 2618 distinct 槽 | 键**过度分散**，几乎无局部性/泛化 |
| 惊讶阈值 | **56%** token 被判「高惊讶+有信息」 | 阈值 3.0 在字级模型上**几乎不筛选** |

**根因一句话**：当前库是「高维 i.i.d. 噪声稀疏查表」——键不过聚类（无泛化）、值仍随机（无组织）、读取太扩散（无 commit）、门控在收缩。唯一不动点是 `gate→0`，即 Δ≈0。

### ⚠ 纠正一个曾被误用的数字
> 之前报的「写入覆盖 99.9%、槽铺满」是**计量 bug**：
> 健康检查用 `(values.norm − 0.125).abs() > 0.01` 判「已写入」，但**随机初始化时值向量范数 ≈1.41**（`randn(128)·0.125` 的向量范数），`|1.41−0.125|=1.28>0.01` → **每个槽天生被判"已写入"**。
> 真实覆盖：**100 步只写了约 0.25%~几个 % 的槽**，记忆库其实**几乎没被用上**（大量闲置槽、写入不回头命中）。

## 五、优化路线（按杠杆排序，全量落地清单）

### P1' ★ 换 value：写「真梯度方向」而非 argmax 残差（改动最小）
**数学**：最优线性修正量不是 `e_y − e_argmax`，而是 **CE 负梯度**：

$$\Delta^* = \sum_k (p_k - \mathbb{1}[k=y])\,e_k = e_y - \mathbb{E}_p[e]$$

实测在高惊讶处和当前 P0 的 cos=**0.82**（不算糟），但 P0 幅值**过冲**（1.08 vs 0.81）——argmax 是硬跳，把「模型没那么确信的错词」当成 100% 确定的错。
**实现**：`val = target_enc(target_emb − Σ_k p_k·e_k)`，需在写路径计算 softmax p。

### P2' ★ 键空间要有局部性，否则永远无泛化（最大杠杆）
PKM 本质是**学习式乘积量化**，128 维下 `h` 的近邻格点**近似随机哈希桶**（4059/4096 查询落互异槽）→ 无两个相似上下文共享槽 → 零迁移。
- 键从「128 维投影」改「低维/结构化上下文特征」（如末 N token id 的 n-gram 嵌入）；
- 或 Locality-sensitive 桶：先把键聚成 K 个「上下文类型」，每簇存**一组**修正（簇级泛化）；
- **共享读写投影**（`q_proj ≡ k_proj`, `q_norm ≡ k_norm`）：消除当前两套独立映射漂移导致的「写时槽 ≠ 读时槽」。

### P3' 读取要 commit + 熵门控
读是「16 个正交向量 × 软权重平均」，top1 仅 0.59 → 被稀释成噪声平均。
- **熵门控**：`gate × f(1−H(top_k))`——检索锐利（低熵）才注入，模糊（高熵）就关闭，把注入强度与检索确定性挂钩；
- 降 temperature / 硬 top-m，避免平均稀释；
- 更彻底：逐槽门控，让聚合由最强命中主导。

### P4' 冻结基座对照（对「是否真增容量」决定性）
基座 81M **全程解冻**。优化器最小化 `CE(logits+注入)`，基座可**在自己的权重里学着复现/抵消 DB 的修正** →「有无 DB」Δ 随训练萎缩。必须加 **`--freeze_base`** 对照：基座冻结、只训接口/门控，非零 Δ 才归因于 DB。

### P5' 惊讶阈值在字级失效；要写「可复现错误」
字级熵高，`loss>3` 覆盖 56%——**不是惊讶，是固有熵**（本来就不可恢复）。应只写**系统性错误**：同一上下文反复预测同一错词（证据累计/槽级投票）才写，或记「中等置信、可学习」的混淆对，不记不可约尾部噪声。

### P6' 写值压缩瓶颈 & 编解码对齐
`target_enc`(512→128) 与读解码器是**两套独立学习**的映射，从未联合对齐——是「目标解耦的瓶颈自编码器」。可绑定编解码（同一矩阵/伪逆），或 **value_dim 提到 n_embd(512)**：库值直接存 n_embd 残差，读解码器恒等/低秩，消除压缩损失。成本 1M×512×2B = **1GB bf16**。

### P7' 换骨架：「偏置注入」→「分布插值」(kNN-LM)
当前 `logits + gate·Δ` 注入依赖一个压缩值 + 门控，不保证合法概率、门控易崩。
**kNN-LM**（Khandelwal et al.）形式更稳：
```text
存 (key=上下文隐层, value=下一token id)
注入: p = λ·p_LM + (1−λ)·p_kNN,  p_kNN ∝ Σ_i exp(−d(q,k_i)/τ)·1[y=y_i]
```
天然：无需编码 value（存 id）、λ 温度退火标准、两分布凸组合恒合法、有真实检索增强 LM 实证。**若目标是"外部库扩容量"，这是最有原则、最可能本质提升的方向。**

### 落地优先级
1. **P1' + P2'(共享投影) + P3'(熵门控) + P4'(冻结对照)** —— 改动小、直接打在实测失效点；
2. P5'（可复现写入门控）+ P6'（value_dim=n_embd）；
3. P7'（kNN 插值）作为骨架级实验，单独跑、单独归因。

## 六、关键结论

1. **外部残差库的机制健康**（值分化/键正交/读写无崩），但**内容低价值 + 键无局部性 + 读太扩散**，导致 Δ≈0。
2. **P0/P2 方向正确**（step25 即 −0.0007 帮助），但 100 步不足；需与 run1 同量级 500 步。
3. **冻结基座是判断"库是否真扩容量"的必要对照**——否则基座会吸收/抵消库的贡献。
4. **P2'（共享投影）与 P3'（熵门控）是最便宜且直接治实测失效点的一步**；P1'（梯度残差）是 P0 的严格升级。
5. P7'（kNN-LM 插值）是最有原则、最可能本质提升的骨架级改法。

## 八、第二轮框架改进（2026-09-09，P8'–P14'）

第一轮（P1'–P7'）虽让 Δ 转负，但诊断暴露了两个**结构性缺陷**——它们才是
「检索≈高维噪声平均、门控只能学成 0」的真正根因。

### 8.1 缺陷一：`retrieve()` 整体 no_grad → 寻址空间永远是随机投影

旧版 `ProductKeyMemory.retrieve()` 整个包在 `torch.no_grad()` 里，而
`q_proj/k_proj/key_norm` 是 `ResidualNeuralDB` 中的可训练层。后果：
**key 投影从未收到任何梯度**，读地址是一组固定随机哈希，
top-1 槽对 4096 个 query 几乎全不同（实测 4059/4096）——库不可能泛化。

**P10' 可微寻址**：top-k 索引仍离散（在 `q.detach()` 上取，保持地址稳定），
但聚合权重 `w = softmax(s_i/τ)` 用**带梯度的 query** 重算所选槽位分数，
于是 `∂L/∂key_proj ≠ 0`。单元测试：旧路径梯度恒为 0 → 新路径 `‖∂/∂key_proj‖ = 0.808`。

### 8.2 缺陷二：未写入槽返回 i.i.d. 噪声

`values` 用 `randn*scale` 初始化，1M 槽绝大多数未写，top-16 软聚合返回的基本是噪声，
门控只能学到「全部关掉」。**P8' 零初始化**：未写槽返回**精确 0**，
读输出只在已写邻域非零；配合覆盖率置信，未覆盖邻域自动不被信任。

| 编号 | 内容 | 动机 |
|---|---|---|
| P9' | 软 top-m **delta 规则** `v_i += ηw_i(t−Σw_jv_j)` | 旧版 top-1 EMA 覆盖 → 各槽各写各的，值场不平滑、不泛化 |
| P11' | **自适应惊讶分位**：只写 batch 内 top-q% | 字级绝对阈值 3.0 命中 56% token，等于不筛 |
| P12' | `slot_support` 改 `index_add_`；usage 零初始化；活跃槽= support>0 | 修统计失真（旧版重复槽赋值 last-wins） |
| P13' | **覆盖率置信** `conf=Σw·1[support>0]` | τ=0.1 下 softmax 熵恒近 0，熵门控无信息 |
| P14' | 温度可调（读/写共用） | 软写入需要更软的 τ 才能让邻居参与 |

### 8.4 关键坑：真实文本热槽导致 delta 规则发散

真实语料中常见上下文的 key 会聚簇，同一 micro-batch 内数十个 query 命中同一热槽
（实测 `slot_support` 直接顶到上限 20）。此时 `index_add_` 的雅可比更新叠加为
`I − η·Σ_q w_q w_qᵀ`，当 `Σ_q w² > 2/η = 10` 时特征值变负 → **槽值发散**。
20 步复现：`values` 最大行范数从 2.8 冲到 **21632**，注入把 val 从 3.92 炸到 12.85（Δ=+8.94）；
而基座自身 val_o 仍为 3.92（证明是注入而非基座问题）。

**修复（归一化雅可比）**：

```
v_s += η · Σ_q w_{q,s}(t_q − p_q) / (1 + η · Σ_q w_{q,s}²)
```

外加两道安全网：`err_clip`（单条误差范数上限）、`value_clip`（槽值范数上限）。
修复后同配置连跑 3 次：vmax 稳定在 1.4~1.7，Δ ∈ [−0.007, −0.004]，不再发散。

### 8.5 单元校验

- 零初始化：未写槽输出精确 0 ✓
- delta 收敛：反复写同一 (key,target) → cos=1.00000、L2 误差 4e−5 ✓
- 泛化：邻近 key（+0.05 噪声）cos=1.00000 ✓
- 可微寻址：`key_proj.grad` 0.808（旧版恒为 0）✓
- 向后兼容：默认参数仍为 randn/ema/top_m=1/无 diff_addr ✓

### 8.6 300 步 A/B 与消融（冻结基座，同一 val 批次配对测 Δ）

| 版本 | Δ@100 | Δ@200 | Δ@300 | 高惊讶Δ@300 | 覆盖 |
|---|---|---|---|---|---|
| 旧框架-冻结（基线） | −0.0564 | −0.0947 | −0.1164 | −0.2618 | 33.4% |
| 新框架 q0.1（无 renorm） | −0.0529 | −0.0559 | −0.0461 | −0.1187 | 9.3% |
| D1 新框架 q0.1 + renorm | −0.0436 | −0.0619 | −0.0260 | −0.0826 | 9.4% |
| **D2 新框架 q0.5 + renorm** | −0.0396 | −0.0622 | **−0.1490** | **−0.3462** | 12.1% |

**D2 反超旧框架 28%（Δ −0.149 vs −0.116；高惊讶Δ −0.346 vs −0.262），且覆盖只用 12.1%。**
轨迹仍在加速（−0.062 → −0.149），未见平台。

### 8.7 关键结论：字级「惊讶」不是好的写入判据

- q0.1（只写最惊讶的 10%）**最差**，q0.5 最好，两者用同一套值/键/门控。
- 机理：高惊讶 token ≈ 稀有 token ≈ 在 val 中**不重复出现** →
  哈希表既无法靠重复写入强化，也无法迁移到新样本。
- 记忆库真正能贡献的是**重复出现的上下文**（高频模式），只有它们才会被反复写、
  槽值才稳定。因此写入判据应从「最惊讶」转向「覆盖广」（q≈0.5~1.0），
  或改用「惊讶 × 频率」的乘积。
- 覆盖 12.1% 却强于旧框架 33.4% → **delta 软写入的每槽信息密度更高**，
  覆盖率不是唯一目标，「写对地方」更重要。

### 8.8 一个被证伪的假设（记录下来避免重犯）

静态分析曾预测「零初始化 + 覆盖率门控 = 二次衰减（c²），是平台化主因」，
并据此实现 `renorm_written`（权重只在已写槽重归一化）。
但 D1（q0.1 + renorm）反而比无 renorm 更差（−0.026 vs −0.046）——
**假设被证伪**：稀释本身起到了正则/保护作用，覆盖率门控不是主因，
写率才是。`renorm_written` 保留为可开关项（默认关）。

## 10. 首次 0.7-epoch co-train 的负结果：DB 被基座吸收（2026-09-09）

### 10.1 结论

**co-train（基座与 DB 同时训练）会使 DB 对推理失去贡献。** 这不是调参问题，而是
"基座自身学习吞掉 DB 角色"的结构性结果。

### 10.2 证据（同一诊断口径 `local/diag_hidden_db.py`，CPU，bs4×blk128×3batch）

| 检查点 | 注入幅度 ‖δ·g‖/‖h₋₂‖ | Δ(on−off) | 放大 10× Δ | 值范数均值 |
|---|---|---|---|---|
| 冻结 E1（300 步，旧基座） | **11.5%** | **−0.342** | +0.811 | 0.0170 |
| co-train @2000 | 1.0% | −0.0017 | −0.0045 | 0.0125 |
| co-train @4000 | **0.60%** | **−0.0002** | +0.0036 | 0.0136 |

训练脚本自带 eval 的 valΔ 同步走平（步 500→4000）：−0.0005 / +0.0001 / −0.0011 /
−0.0006 / −0.0002 / −0.0009 / −0.0003 / −0.0004。

### 10.3 机制（静态分析）

写入目标 `val = target_enc(target_emb − E_p[emb])`，写入量 `η·w/(1+ηΣw²)`，`η=0.2`：

1. **目标随基座收敛而收缩**：`E_p[emb]` 越接近 `target_emb`，残差越小 → 值越写越小。
2. **槽位几乎不复写**：`slot_support` p50 = 0.197（p90 = 3.24），一半以上已写槽支持度
   不足 1 —— 无覆写/遗忘机制，早期写入长期滞留。
3. **基座在移动**：每步基座都在变，已写值迅速过时。三者叠加 → 注入幅度随步数单调衰减，
   内容由"有用"（@2000，放大 10× 仍有益）变"有害"（@4000，放大 10× 明显变差）。

关键区分：冻结 E1 的 −0.34 主要来自"旧基座 vs 新多源语料"的**错配修正**（含适应成分），
不能拿来预测收敛基座上的 DB 收益。

### 10.4 对本项目目标的影响

目标"在不增加模型规模的前提下提升有效容量"要求 DB 在推理时**承担负载**。
co-train 下 Δ≈0，DB 不承担负载 → 该 regime 不成立。正确形态是**两阶段**：
先把基座训到收敛，再冻结基座训练 DB（即项目最初设想）。

### 10.5 已部署的运维设施

- `local/watchdog_db.sh`：独立会话看门狗；进程死亡自动 `resume_db_07ep.sh` 续训
  （限流 4 次/小时），存活但 16 分钟步数不动则告警。
- `local/status_db.sh`：一条命令输出进程/进度/评估历史/异常。
- `local/diag_hidden_db.py`：CPU 上的注入幅度 + on/off + 放大诊断（零 GPU 占用）。
- 踩坑：tqdm 4.70 的 `pbar.write()` 走块缓冲流，不加 `-u`/`PYTHONUNBUFFERED=1` 时
  eval 行会滞留缓冲区直到进程退出 → 训练脚本必须 `-u`（已写入 `run_db_07ep.sh`）。

### 10.6 当前决断（用户 2026-09-09）

保持基座训练到 0.7 epoch（DB 暂不干预），Phase-2（冻结基座 + 训练新 DB）在基座训练
告一段落后执行。待办：导出 cojoint 基座权重为 best.pt 格式、写 Phase-2 启动脚本，
并针对 §10.3 三条机制改造写入规则（覆写/衰减、更大写入增益、写判据 = 惊讶×频率）。

## 11. 审查（2026-09-09 晚）：第三条独立证据与设计重定向

### 11.1 基座进展（健康）

- 进度 13494/71419（18.9%），16h43m，1836 tok/s，显存 3.70G/4.91G，ETA ≈ 72h。
- val_o：3.1333@500 → 2.1979@13000（−0.935 nats / 12.5k 步）。
- 评估间噪声 ±0.11 nats（≈4.6%）：`eval_iters=15 × batch8 × blk256` 随机抽 120 个窗口，
  点间抖动（2.09↔2.38）无意义；Δ 是同批次配对量，噪声抵消，故 1e-4 分辨率的 Δ 可信。
- 外推 @71419：幂律 1.77 / 饱和式 1.82 → **0.7 epoch 预计 val ≈ 1.75~1.85**。

### 11.2 忠实 Phase-2（CPU：冻结基座 + 全新 DB + 训读侧 1500 步）

`local/cpu_phase2_mini.py --train_iface`，同一配对 val 批次：

| 基座 | val_o | Δ_on | Δ_x10 |
|---|---|---|---|
| 旧 best.pt @300 | 3.6430 | **−0.3521** | +2.7460 |
| 当前 cojoint @4000 | 2.4573 | **−0.0034** | −0.0073 |

**换一个全新 DB 也救不了收敛基座**：Δ 从 −0.35 掉到 −0.0034。因此 co-train 的"吸收"
不是"同时训练导致遗忘"，而是"基座一旦收敛，残差 DB 本就无事可做"。
（旁证：当前基座 @4000 已 2.457，比旧基座+DB 的 3.643 低 1.19 nats。）

### 11.3 衰减规律（26 个配对评估点）

- 全程均值：Δ = −0.00035（相对 0.014%），高惊讶 Δ = −0.0051（相对 0.20%）。
- 前 8 点 vs 后 8 点：Δ −0.00049 → −0.00022；高惊讶 Δ −0.00793 → −0.00298，**单调衰减**。
- 线性拟合 hiΔ ≈ 0.00255·ln(step) − 0.0269 → **约 step 38.6k 穿零**。
- 直接反驳"早期写入是垃圾、后期会变好"：方向相反，是"早期域适配红利随基座追上而消失"。

### 11.4 数学根因

写目标 r = target_emb − E_p[emb]，槽位读出 ≈ E[r|h]。基座在 h 条件下校准 ⇒ E[r|h]=0 ⇒ Δ=0。
‖r‖≠0 只是 per-token 方差（valnorm 0.012~0.014），不是 h 可预测的系统偏置。
**残差 DB 只能学"基座的条件系统偏差"，而梯度下降正在把这份偏差清零。**
旧基座的 −0.35 是域错配（旧对话数据 vs 新多源语料）产生的系统偏置；x10=+2.75 说明那是
一次窄的线性修正，不是记忆。

### 11.5 设计重定向：残差纠正器 → 检索式（kNN-LM）

要让增益不随基座收敛而消失，写入目标必须是**基座无法内化的东西**：训练流该位置的真实下一
token（或其分布）；读时在 logit 层混合 p = (1−λ)·p_model + λ·p_knn。现有 product-key
索引（4.19M 槽、key=h）可直接复用，只改 value 与读出：

- value：残差向量 → 目标 token id（`product_key_memory.py` 已有 `token_ids` buffer，P7 雏形）。
- 读出：h 注入 → logits 混合（训练/推理脚本改动，属 Phase-2）。
- 只写高惊讶位置控制库大小；λ 可调。

这是唯一在 0.7 epoch 乃至多 epoch 尺度上仍有可观 Δ 的路径。

1. 当前 co-train 是否保持到 0.7 epoch（DB 侧开销按算子量 <2%，无害）。
2. 是否现在离线实现 kNN-LM 变体（新增文件，不触碰运行中任务导入的模块）。

`鼓→劲`、`最高检→呈`、`通→盘`、`搜→表`、`肉酱香肠→焗`、`主簿董→厥`……
且目标 token 本身常很常见（劲 13.6 万次、表 79 万次、突 20 万次）。
**结论：瓶颈不是 token 稀有度，而是"上下文→token 关联"的存储容量。**

### 12.2 残差式 DB 为何不可能承担负载（形式化）

写目标 `r = e_y − E_p[e]`（`e` = token 嵌入，`p` = 基座分布），槽位读出 ≈ `E[r|h]`。
当基座在 h 条件下校准，`E[e_y|h] = E_p[e]` ⇒ `E[r|h] = 0` ⇒ 注入 ≈ 0。
`‖r‖≠0` 只是 per-token 方差。**残差 DB 能学的只有"基座的条件系统偏差"，
而梯度下降正在把这份偏差清零；它对"基座无法表示的关联"没有任何入口**，
因为写目标被 `E_p` 过滤掉了。

### 12.3 n-gram 记忆探针：精确检索能拿多少（`local/ngram_memory_probe.py`）

用纯 CPU 在训练流前缀上建"上下文 → 下一 token 多数投票"表，与模型分布按
`p = (1−λ)p_model + λ·onehot(多数)` 插值，val 为**文档级不相交**切分（`prepare.py`
按 block shuffle 切 90/10，无泄漏）。基线 off loss = 2.3068。

**前缀 100M tokens（12% 全量流）**：

| 上下文长度 | 表条目 | 覆盖率 | 覆盖内命中 | 最优 λ | 最优 Δ |
|---|---|---|---|---|---|
| L=4 | 34.7M | 37.6% | 20.5% | 0.05 | −0.0068 |
| L=6 | 54.2M | 9.7% | 43.1% | 0.05 | −0.0129 |
| L=8 | 63.4M | 4.9% | 61.6% | 0.2 | **−0.0161** |
| L=12 | 73.8M | 3.3% | 70.4% | 0.3 | **−0.0157** |
| backoff 4/6/8/12 | — | 37.6% | 25.8% | 0.05 | −0.0142 |

**四条结论**：

1. **纯检索、零训练梯度**，100M 前缀就拿到 Δ ≈ −0.016，是当前残差 DB（−0.0003）的
   **约 50×**，是忠实 Phase-2（−0.0034）的 **约 5×**。
2. 最优 λ 很小（0.05–0.3），收益集中在**高阶上下文**（L=8/12）；L=4 在 λ>0.1 时有害。
3. 插值收益的判据：`dΔ/dλ|₀ = A/p − 1`，即**检索命中率 A 必须超过模型自己的正确概率 p**
   才有净收益 ⇒ 必须按置信度门控 λ（高熵/低 p 的位置才混入）。
4. **覆盖率随流规模增长很慢**（L=8：2.5%@30M → 4.9%@100M），说明瓶颈是**条目数/槽位数**，
   不是数据量。100M 前缀的 n-gram 表已有 2100 万–7400 万条，而当前 DB 只有 **419 万槽**——
   要复现这个精度，槽位数要涨 10–30×。（注：`cov(P)=1−exp(−kP)` 外推给出 L=8 全量
   43%，两点幂律外推只给 9%；真实值在两者之间，需用全量建库实测。）

### 12.4 设计建议：PK-Retrieval v3

| 维度 | 现状（v2） | 建议（v3） | 理由 |
|---|---|---|---|
| Key | 仅隐藏态 h₋₂ → 32 维 | 隐藏态 ⊕ 后缀 n-gram | 后缀 key 保精度（12.3），隐藏态 key 保泛化 |

代码基础已具备：`product_key_memory.py` 有 `token_ids` buffer（P7），

## 13. 检索式记忆的值编码与容量预算（全流随机采样修正版）

### 13.1 决定性修正：训练流是「源有序」的

`data/chinese/prepare.py` 按 `sorted(os.listdir)` 逐文件拼接，`train_char.bin` 因此
按来源成块排列：

| 偏移 | 内容 |
|---|---|
| 0–5M | SEO 垃圾站（"亚美优惠…AG发财网"、"精品国产福利在线视频"、"福彩3d预测"） |
| 30M | 中文新闻/公文 |
| 60M | 更多垃圾站（"2分时时彩"、"大发快3"） |
| 100M | 英文代码文档（`es a single parameter 'lst'…`） |
| 200–400M | 数学 CoT / 逐位进位 |
| 700M | 中文百科（巴伐利亚球队…） |

而 val 是**各源 10% 文档级切分**（`val_all=True`），源分布均衡。所以
**顺序前缀建库 = 只覆盖前几个源**，对 val 的覆盖率被严重低估：

| L=6，建库 60M tok | 覆盖 val | top1 命中 | 最优 Δ |
|---|---|---|---|
| 顺序前缀（§12.3） | 7.5% | 48.0% | −0.0117 |
| **全流随机采样** | **40.2%** | **70.2%** | **−0.0141** |

**工程结论：DB 建库必须全流随机采样或先打乱，绝不能顺序扫前缀。**

**数据质量提醒**：对 20M 间隔抽样分类（粗分类）：中文文本 55% / 代码 19% /
数学 12% / **垃圾站 7%** / 对话 7%。c4_zh.txt 单文件 489MB（约占 58%），其中的
SEO 垃圾（时时彩/快3/大发）建议数据治理后再训下一版。

### 13.2 值编码：count 加权 > hard top-1（一致但幅度小）

60M 全流采样建表，同一 key、同一覆盖集，只改 value 编码：

| L | 覆盖内 top1 命中 | hard Δ* | soft(top-3 计数加权) Δ* | soft 增益 |
|---|---|---|---|---|
| 6 | 70.2% | −0.0129 (λ=0.1) | **−0.0141** | +9.3% |
| 8 | 77.6% | −0.0134 (λ=0.2) | **−0.0150** | +11.9% |
| 12 | 81.6% | −0.0160 (λ=0.2) | **−0.0161** | +0.6% |

**结论：槽里应存「token 计数」（至少 top-3），读出用计数加权**，比硬 top-1 稳定好
5–12%；且计数天然提供置信度（供 λ 门控）。最优 λ 仍很小（0.1–0.2）。

### 13.3 容量曲线：4.19M 槽能拿约一半，16.8M 拿约七成

「只保留计数最高的 M 条上下文」——这是 M 槽的**乐观上界**（真实 product-key 有碰撞）：

| M | L=6 soft Δ | L=8 soft Δ | L=12 soft Δ |
|---|---|---|---|
| 1M | −0.0065 | −0.0052 | −0.0031 |
| 4.19M（当前） | −0.0085 | −0.0073 | −0.0101 |
| 16.8M | −0.0105 | −0.0096 | −0.0122 |
| 全部（40–52M 条） | **−0.0141** | **−0.0150** | **−0.0161** |

- 当前 4.19M 槽 ≈ 满容量的 **49%（L=8）~63%（L=12）**；16.8M ≈ 65–76%；67M 接近饱和。
- 曲线在 log-M 上近似线性 → 槽位数是**收益的对数放大器**：16× 槽位换约 +40% 的 Δ。
- 真实 product-key 有哈希碰撞，实际要打折；但**「4.19M 太小、16.8M 起步、67M 上限」
  的预算结论成立**（修正 §12.4 中「要涨 10–30×」的过强表述）。

## 14. 神经元级神经数据库 v5：从 token 到神经元（2026-09-09 夜）

### 14.1 方向修正

用户判定：token 级 DB（存"下一 token 计数"）与 harness 记忆工具无本质区别，改为**神经元级**——
value 是残差流空间的向量，不是 token 分布。§13 的「写 token 计数」据此作废，
P0-1 改为「写神经元向量」。

### 14.2 value 的数学选择：−∂CE/∂h 完胜 Δh

`local/diag_neuron_value.py` 在 h[-2] 注入**单位范数**扰动，量 CE 变化（Δ<0 有益）：

| 方向（单位范数） | η=0.05 | η=0.1 | η=0.3 | η=1.0 | η=3.0 |
|---|---|---|---|---|---|
| **−∂CE/∂h（梯度）** | −0.0137 | −0.0272 | −0.0812 | **−0.2625** | **−0.7192** |
| Δh = h_{t+1}−h_t | −0.0007 | −0.0013 | −0.0041 | −0.0134 | −0.0386 |

- ‖g‖/token = 0.274，‖Δh‖ = 57.7；cos(ĝ, Δĥ) 均值 **−0.020**，仅 3.7% 的 token |cos|>0.2。
- **Δh 与真正的神经元修正方向几乎正交，效果弱 20 倍**；且 Δh 全量注入有害
  （oracle +4.38，因为它是"下一个预测器的状态"，加到 h_t 上会跳过当前 token）。
- 结论：value 定为 **−∂CE/∂h**，保留 `--value delta` 开关。

顺带修掉一个 ROCm bug：`(N,128) / (N,)` 隐式广播在 gfx1030 上会误报
"size of tensor a (128) must match b (N)"，显式 `.unsqueeze(1)` 即可。

### 14.3 v5 形态（`model/neuron_db.py` + `local/neuron_db_v5.py`）

```
key   = 精确后缀 L=8 多项式哈希（4.19M 槽，64 位全哈希校验）
value = E[−∂CE/∂h | suffix]        512d 神经元向量，固定随机投影到 128d 存储
store = 有序无梯度矩阵 (hash, count, value)，永不被 optimizer 触碰
read  = h_t ← h_t + λ·decoder(value)，λ = sigmoid(gate(h)) × 覆盖
接口  = decoder(128→512) + gate(512→1)，共 66K 参数，基座冻结
```

关键：**decoder 初始化为投影伪逆**，冷启动即等价于"小系数注入检索到的真值"
（随机初始化会让冷启动注入变成噪声）。

### 14.4 首次实测（20M 建库 + 2000 步接口训练）

建库：20M token 目标，实际**成功写入 6.5M 条**（68% 因哈希碰撞被跳过），
填槽 4,112,979/4,194,304（**98.1%**），均 count **1.57**，store 1.12GB，耗时 1411s。

接口训练 2000 步（342s）：decoder 范数 13.1 → 94.7（持续放大），门控 λ 0.119 → 0.160。

评测（1024 窗口 = 262k token，训练后接口）：

| 指标 | 值 |
|---|---|
| base（DB off） | 2.2514 |
| 覆盖率 q | 24.2% |
| cos(dec, 真值梯度) | 0.070 |
| **学习门控 Δ** | **−0.0039** |
| oracle Δ（真梯度 λ=1） | −0.1244 |
| 固定 λ 扫描 | 0.1→−0.0005, 0.3→−0.0014, 0.5→−0.0022, 1.0→−0.0038 |

**判定：机制成立**（Δ<0 稳定，随训练单调改善），但只拿到 oracle 天花板的 **3.1%**。
对比 token 级 n-gram（60M 写入）的 −0.015，当前神经元级弱约 4 倍。

两个观察：
1. **decoder 范数单调放大 13→95**：优化在"放大弱信号"，是病态（ill-conditioned）而非发散。
2. **"冻结基座"并不冻结**：base loss 跨 eval 从 2.3288 漂到 2.3468（+0.018），
   因为 aux-free MoE 的 router_bias 在每次 forward 内就地更新（no_grad 副作用，
   见 `model/gpt.py` 注释）。配对 Δ 仍然有效，但绝对 loss 不可用。

### 14.5 收敛性：条件收敛，不发散

设计模型（三时间尺度）：

```
θ̇ = −η_θ ∇_θ L(θ,φ,v)        基座（慢）
φ̇ = −η_φ ∇_φ L(θ,φ,v)        接口 decoder+gate（中）
v̇ = β ( V(θ) − v )           库内容（快），V(θ)(k)=E[−∂L/∂h | k]
λ = σ(wᵀh+b) ∈ (0,1)          有界 —— 不发散的结构性保证
```

- **命题 1（v5，冻结基座 + 固定库）**：F=L 本身是 Lyapunov 函数，
  dF/dt = −η_φ‖∇F‖² ≤ 0，F 有下界 ⇒ 收敛到局部极小。**不发散。**
- **命题 2（吸收）**：键 k=ψ(h) 时校准下 E[∂L/∂h|h]=0 ⇒ v=0 是不动点，
  线性化 v(t+1)≈(1−β(1−ρ))v，0<β<2 时全局吸引。
  **"DB 被基座吸收"= 快速收敛到平凡点，不是发散。**
- **命题 3（外生键）**：键与 θ 无关时，不动点
  **v* = 基座函数类 F_θ 之外的条件残差 R(k)**。
  基座能表达 ⇒ v*=0（平凡）；不能表达 ⇒ v*≠0（非平凡）。
- 发散只来自：步长过大、时间尺度不分离且环路增益>1、库值滞后到反相关、门控无界。
  v5 的 sigmoid 门控 + running-mean 库值天然规避后两条。

真正的风险是**收敛慢（病态）**：∇²F ≈ λ²Vᵀ(JᵀHJ)V，若库值方向高度共线则
λ_min→0，表现为"训练不动"。监控量：‖∇_φF‖、门控 λ 分布、‖D‖、train/val Δ 差。

### 14.6 瓶颈与下一步

当前有效 R² ≈ Δ/oracle ≈ 3%（按同 λ 口径），覆盖率 24%。数学上
```
Δ ≈ q · R² · (G²/2λ_H) · SNR/(1+SNR)
```
三个杠杆里，**q 和 R² 都还没打满**：
- 槽位 4.19M 在建库阶段 98% 饱和、均 count 仅 1.57 → 估算噪声大（cos 被压低），
  且覆盖率受表大小限制；
- 后缀键只解释了约 3% 的梯度能量 → R² 是主瓶颈。

待验证（按杠杆排序）：
1. **接口训练更长**（Δ 在 2000 步时仍单调改善，未饱和）；
2. **加大写入量 / 缩小表**：把均 count 从 1.57 提到 ~10，压低估算噪声；
3. **门控接入 count**：λ* 依赖 n_k，而 h 里没有 n_k（数学预测 P2）；
4. **键增强**：后缀 ⊕ 隐藏态混合键（隐藏态单独作键 R²=0，见命题 2）。

### 14.7 走 B 前的诊断：未来多步隐藏态太弱（2026-09-09 夜）

用户决定跳过 A、直接走 B（换监督目标，让 value 携带 token 之外的信息）。
先测 B 的 oracle：`local/diag_future_value.py` 在 h[-2] 注入单位范数方向，量 Δ（<0 有益）：

| nn_h（最近邻 h_j） | +0.0006 | +0.0019 | +0.0065 |
| nn_hn（最近邻 h_{j+1}） | +0.0002 | +0.0005 | +0.0028 |
| nn_d（h_{j+1}−h_j） | −0.0004 | −0.0010 | −0.0012 |
| mean_h（top-8 均值） | +0.0005 | +0.0019 | +0.0069 |
| mean_hn（top-8 下一态均值） | +0.0001 | +0.0005 | +0.0029 |

关键：**cos(h_t, 最近邻 h_j) = 0.824**。

**结论：检索到的神经元向量 82% 与当前状态冗余，注入它不帮（甚至有害）；
唯一略有帮助的是"状态转移" nn_d（−0.0012），仍比梯度弱 600 倍。**

**机理**：基座的 h_t 已经把它能从相似上下文压缩出来的信息都编码进去了。
外部再喂一个"相似上下文的神经元向量"，大部分只是把 h_t 的方向又加了一遍。
**基座缺的不是神经元级信息，而是 token 级的离散信息**（确切的续写），
这解释了为什么 token 级 n-gram（−0.015）和 token 级梯度（−0.0039）有效，
而一切"神经元内容检索"都无效。

⇒ **B（外部神经元向量记忆）前提不成立。** 除非价值来自当前 256 窗口之外
（真正的长程上下文），否则神经元级检索是冗余的；而长程需要先扩上下文
（RoPE 外推 + 联合训练），是另一个量级的工程。

### 14.9 杠杆验证：覆盖率 > count，缩表是错的（2026-09-10 凌晨）

同一批 20M token，只改表大小，做对照：

| 表 | 成功写入 | 填槽 | 均 count | 覆盖 val | cos | 学习门控 Δ | oracle |
|---|---|---|---|---|---|---|---|
| 4.19M | 6.5M | 98.1% | 1.57 | 24.2% | 0.070 | **−0.0039** | −0.124 |
| 1.0M | 2.6M | 100% | **2.48** | 17.6% | 0.055 | **−0.0014** | −0.124 |

**缩表把 count 从 1.57 抬到 2.48（1.58×），但成功写入从 6.5M 掉到 2.6M（0.40×），
覆盖率从 24.2% 掉到 17.6%，Δ 反而变差 2.8×。**

结论：
1. **count 不是瓶颈**——数学上估算 SNR≈0.05、增益 ∝ n 的预测没有兑现；
2. **覆盖率（不同键的数量）才是主杠杆**：表越小，丢的键越多，而且留下的都是高频
   后缀（对应更"容易"的位置），R² 也下降；
3. 要提高收益，正确方向是**更多写入 / 更大表**（更多不同键），而不是缩表堆 count。

按 n-gram 外推：4.19M 表 + 60M 写入 → 覆盖 ~30%、count ~4.7，Δ 有望到 −0.01 量级
（仍未验证，建库 ~70min）。

### 14.10 v6：后缀回退 + 收缩估计 + count 门控（2026-09-10）

针对 §14.9 的两条结论（覆盖率是主杠杆、单次观测估值噪声大）落地三项改动，
其余（value=梯度、4.19M 槽、20M 写入、decoder 伪逆初始化）保持不变：

1. **多级后缀回退（backoff）**：键从单一 L=8 扩为三级 L=12/8/6，最长匹配优先。
   不同长度的后缀是**不同的键**，等价于在相同槽预算下扩大有效键空间。
2. **收缩估计（shrinkage）**：`v̂ = n/(n+κ)·mean`，κ=3。
   均 count 只有 1.5~2.6 时，单次观测的估值噪声被压掉。
3. **count 门控**：`λ = σ(gate(h) + α_lvl + β·log1p(n))`。
   §14.6 已指出 λ* 依赖 n_k 而 h 里没有 n_k，这里显式补上；
   每级一个 α_lvl（低质量的长尾级可整体降权）。

实测（1024 窗口 = 262k token，接口训练后）：

| | 覆盖 | cos | 学习门控 Δ | oracle |
|---|---|---|---|---|
| v5 单级 L8 | 24.2% | 0.070 | −0.0039 | −0.1244 |
| **v6 三级 L12/8/6** | **32.6%** | **0.075** | **−0.0046** | −0.1244 |

命中按级别分布：L12 38% / L8 39% / L6 23%。

**解读**：

- 覆盖 1.35×，但 Δ 只 1.18×。每覆盖位置的效率从 0.0161 降到 0.0141，
  因为 L6 兜底命中质量更低（它命中的是模型本来就更容易的位置）。
- **size-biased count**：命中位置的加权均 count（Σc²/Σc）为 L12:82 / L8:134 / L6:383，
  而槽均 count 只有 1.46/1.57/2.56。命中高度集中在少数超高频后缀上——
  这是覆盖率指标本身的隐性成本，也解释了"提覆盖率"的边际收益为什么在递减。
- 256 窗口的 step-2000 检查点 Δ=−0.0051，与 1024 窗口同量级，结论可信。

**结论**：backoff 是正收益但递减；再上一个台阶需要新杠杆（§14.11）。

### 14.11 注入层扫描：越早越强，h[-6] 是当前最优（2026-09-10）

`local/diag_layer_scan.py` 把「单位范数 −∂CE/∂h」注入到不同层，量 CE 变化（Δ<0 有益）：

| 注入层 | ‖g‖ | Δη=0.3 | Δη=1.0 | Δη=3.0 |
|---|---|---|---|---|
| h[-1] | 0.284 | −0.0841 | −0.2720 | −0.7442 |
| h[-2]（v5/v6 当前） | 0.274 | −0.0811 | −0.2625 | −0.7192 |
| h[-3] | 0.302 | −0.0893 | −0.2866 | −0.7706 |
| h[-4] | 0.335 | −0.0991 | −0.3152 | −0.8256 |
| **h[-6]** | **0.450** | **−0.1314** | **−0.4045** | **−0.9630** |

**h[-6] 的 oracle 比 h[-2] 强 1.54×（η=1.0：−0.4045 vs −0.2625），且 ‖g‖ 单调增大。**

机理：注入越早，修正量经过的下游层越多，被网络放大的空间越大。
这是一个**几乎零成本的改动**（只改 hook 的层号），且与覆盖率 / backoff 正交。

**待验证**：

1. 扫描延伸到 h[-8]/h[-10]，确认峰值（可能更早）；
2. oracle 更强 ≠ 端到端更强——早层梯度更"抽象"，后缀键能解释的比例（R²）可能更低，
   必须用完整 v6 流程在 h[-6] 重跑一次，才能确认净收益。

### 14.12 多向量槽（mixture）是负结果：内存 2× 反而 0.54×（2026-09-10）

**动机**：单槽只存条件均值 E[−∂CE/∂h | k]，而 §14 观测到槽内方差占 97%，
怀疑"多峰续写被均值抹平"。实现见 `model/neuron_db_mix.py`：每槽 K 个模态，
写入归到最相似模态（在线 K-means），读取用学习查询 q(h) 对模态打分后 softmax 加权。

**配置**（与 v5 严格对齐，单级 L8:22、20M 写入、6.46M 条、4.19M 槽、同一批 val 窗口）：
唯一不同是 `--modes 2 --value_dim 128`，即每槽 2×128 = 256 维，**内存是 v5 的 2 倍**（mix.pt 2.1GB）。

| | 覆盖 | cos | 学习门控 Δ（1024 窗） | Δ（256 窗 step2000） | oracle |
|---|---|---|---|---|---|
| v5 单槽 | 24.2% | 0.070 | **−0.0039** | −0.0051 | −0.1244 |
| **mixture K=2** | 24.2% | 0.066 | **−0.0021（0.54×）** | −0.0032（0.63×） | −0.1244 |

训练轨迹（256 窗）：step500 −0.0011 → 1000 −0.0019 → 1500 −0.0027 → 2000 −0.0032，
单调改善但**全程落后 v5**。

**结论：多向量槽（当前实现）是负结果——内存翻倍、收益腰斩。**

机理推测（按可能性排序）：

1. **收缩噪声**：写入按模态均分，每模态 count 约减半（~0.8 vs 1.57），
   收缩估计 `v̂ = n/(n+κ)·mean`（κ=3）把每模态值压到 ~0.21（单槽 ~0.34）→ 信号更弱。
   这是**混淆项**，不是干净的否证。
2. **h→mode 映射学不动**：cos 从 0.070 降到 0.066，读侧查询没能有效选中模态，
   softmax 平均退化成"单槽均值 + 额外方差"。
3. **槽内方差是不可约噪声**：97% 槽内方差里能被 h 预测的多峰成分很少，
   一阶条件均值已经是当前 SNR 下的最优统计量。

⇒ 代码保留（`--modes` 默认 1），不投入。若要翻案，先做两个便宜对照再判：
**κ=0 的 mixture**（排除收缩 confound，store 不用重建）与 **value_dim=64**（内存对齐）；
但优先级低于 §14.11 的注入层。
