# 52-基础设施优化方案与项目演进路线

日期：2026-09-01  
定位：总结 EOS 修复与字符直入阶段性成果，规划下一阶段基础设施升级与模型能力演进路线。

## 一、 基础设施优化方案（工程与算力效率）

### 1. 训练数据加载与流水线
- **瓶颈**：`train.py` 的 `get_batch` 单进程同步 `np.memmap` 随机切片，每 step 与 GPU 前向串行。
- **方案**：
  1. **异步双缓冲加载器**：CUDA 预取线程（`prefetch_factor=2` + `pin_memory=True` + `non_blocking=True`），与前向反向并行完成切片与 Host-to-Device 传输。
  2. **Inductor 编译持久化缓存**：配置 `TORCHINDUCTOR_CACHE_DIR` 与 ROCm Triton 预编译产物持久化，消除反复启动的 5~6 分钟重复 JIT。
  3. **内存防 OOM 护栏**：自动化脚本设虚拟内存软限制 + 外部任务并发检测。

### 2. 推理与部署
- **瓶颈**：`chat.py` / `sample_py.py` 自回归每 step `torch.cat`，反复显存重分配与拷贝。
- **方案**：
  1. **静态 KV Cache / 滑窗 Buffer**：预分配 `block_size=256` KV 缓冲、游标 In-place Write，显存分配 $O(T)$ → $O(1)$。
  2. **MTP 投机验证解码**：已训练 2-Step MTP 头（预测 $t+1, t+2$），每步前向产出 2~3 候选 token、下一步单次前向并行验证，流式吞吐 **1.8× ~ 2.5×**，无需 Draft Model。
  3. **INT8 量化 + Rust 运行时导出**：因式分解嵌入（24d）+ 6L MoE 权重导出 INT8 / GGUF，2.70M 模型 footprint 压至 **~1.5MB**。

## 二、 模型架构与算法演进路线
路线：词表 Byte-Fallback Char Tokenizer（100% 覆盖零 unk）→ 推理 MTP Speculative Decoding（单步 2~3 token 投机验证）→ 对齐 SimPO/DPO 极简偏好微调（消除模板感）→ 记忆自适应时间衰减门控（解决超长轮次上下文漂移）→ 语料 Data Mixture v3（日常/百科/情感三元重平衡）。

### 1. 词表与表征：Byte-Fallback 字符分词器
- **现状**：4623 词表消除 BPE 话术死锁，但生僻字/专业英文符号/emoji 退化为 `<unk>`。
- **目标**：WordLevel (4000 常用字) + 256 UTF-8 字节 fallback；常用汉字 1 token，非常规字符回退 2~3 字节 token，兼得字级高效与 100% 覆盖、零 `<unk>`。

### 2. 对话智能与偏好对齐 (SimPO / DPO)
- **现状**：共情对话语感良好，但对非情感类指令也会习惯性给安慰性回答。
- **目标**：1000 条正负偏好对话对（$y_w$ 恰当回答 vs $y_l$ 答非所问/过早套话），SimPO 200~300 步微调，零额外参数、无需 Reward Model，学会"问天气答天气、倾诉时再共情"：
  $$\mathcal{L}_{\text{SimPO}} = -\log \sigma \left( \frac{\beta}{|y_w|} \log \pi_\theta(y_w|x) - \frac{\beta}{|y_l|} \log \pi_\theta(y_l|x) - \gamma \right)$$

### 3. 长程记忆与话题切换
- **目标**：KV 记忆注意力引入**自适应时间衰减门控**，检测全新话题时降低前序记忆保留权重，避免多轮（>10 轮）上下文串味：
  $$\gamma_t = \text{sigmoid}(W_\gamma x_t + b_\gamma),\quad M_t = \gamma_t \odot M_{t-1} + (1 - \gamma_t) \odot \Delta M_t$$
