#### 0.5.1 ⭐ 有效 token 密度只有 39%，有效语料只有全库的 6.14%

| 口径 | 实测值 | 怎么来的 |
|---|---:|---|

1. **算力效率：39.3%** → 被前向的 8192 个 token 里有 **61% 不产生梯度**（同一个窗口内

2. **语料利用率：6.14%** → 全库 937.8M token 里，模型**一辈子只能见到 57.6M**。

#### 0.5.3 eval 噪声：机制已定位，σ≈0.087

`results.csv` 的 val 相邻差分 sd = **0.193**（全程）/ **0.127**（11000 步后），
而每千步真实进展只有 0.02~0.04 → **单点噪声是信号的 3~5 倍**。

**为什么**：有效独立单元是**窗口**，不是 token。窗口级 CE 极度不均匀
（per-token CE 分位 p50 0.385 / p90 6.05 / p99 10.2），实测 **σ_window ≈ 2.0 nats**。
两条完全独立的路径给出同一个值，互相验证：

```
由 last_step_loss（每步 32 窗口）去趋势 sd 0.3786  → σ_window = 0.3786×√32  = 2.14
由 window_mean（20 步 = 640 窗口）去趋势 sd 0.0795 → σ_window = 0.0795×√640 = 2.01
```

于是训练那次 eval（`eval_iters=200` × `batch_size=4` = **800 个窗口**）的
**σ_eval = 2.0/√800 = 0.071**。三种独立测法：

| 测法 | σ_eval |
|---|---|
| 由 σ_window 推算 | 0.071 |
| 配对重评脚本的 800 窗口分块 sd（实测，ckpt 5000） | **0.0865** |
| `results.csv` val 相邻差分（11000 步后） | 0.090 |

→ **采用 σ_eval ≈ 0.087。** 推论：单点 val 只能分辨 >0.3 的差异；要测 0.02~0.07 的
NDB Δ **必须配对**（`scripts/ndb_online_ab.py` 已是该设计，别改）。
要把 σ 压到 0.03 需要 `eval_iters≈2200`（代价 ≈ +15% 墙钟），不划算——
**用 ≥5000 步聚合，或配对重评**。

⚠️ **`data/chinese/DATASET_REPORT.md` §"结论摘要"第 2 条写的"val CE 的标准误在 1e-3
nats 量级"是错的**（它按 token 独立算，实际单元是窗口），**差了约 70 倍**。
那条错误结论会诱导人相信"单点 val 可比"，必须修。

三条读法：

1. **"读上下文"是真的，且在快速变强**：`real − shuffled` 从 **0.459 → 2.050 nats（4.5×）**；

2. **20000 → 40000 是全场最大的一跳**（散文 −1.21、对话 −1.33、代码 −1.30 nats）——

### 6.2 ★ 为什么"写残差"注定失败 —— 定理级（§11.4 / §12.2）

### 12.3 「模型自己决定读写」落在哪
```
【写】模型决定写多重   w_t = σ(W_w · h_t)              ← 可学习写门控
【读】模型决定信多少   g_t = σ(W_r · [h_t; 槽统计量; w_t]) ← 可学习读门控
【级】模型决定信哪级   α = softmax(level_weight)        ← 可学习多级混合
       p = (1−g_t)·p_model + g_t·Σ_L α_L·p_ng^(L)
      槽统计量 = [log(1+total), top1占比, 槽是否非空]（全是推理时可得、无标签）
```

**梯度路径（诚实说明，别假装是严格端到端）**
```
✓ ∂L/∂W_r ≠ 0           读门控直接可微，路径干净
✓ ∂L/∂level_weight ≠ 0  多级混合直接可微
△ ∂L/∂W_w ≠ 0           **但不是通过"写"来的**：离散表阻断了跨 batch 的梯度链。
      本实现让 w_t 同时作为 read_gate 的输入特征 → W_w 从读侧拿到真实梯度。
      是合理的归纳偏置（"想读的地方就多写"），**不是**严格的写信用分配。
```
