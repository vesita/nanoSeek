# 27-数据重平衡与多轮修复（D 诊断 + A1 重平衡，2026-08-19）

## 背景：你好体检（dev-notes/你好体检-ab2-qkv.md）结论
- EOS 自吐 ✅ 10/10、重复度 ✅ rep3≈0、**对话自然度 ❌**——内容瓶颈 = 数据构成。
- 附加发现：turns=0/10，模型 EOS 后**不续轮**，只会继续吐心理咨询师话术碎片。

## D 诊断：为什么模型不续轮（两条机制）

### 机制 1：数据构成失衡
train.bin 实测构成（抽样外推）：
| 源 | 性质 | tokens | 占 train |
|---|---|---|---|
| zhuangxialie | 单轮情感支持 Q&A | ~41.6M | **57.1%** |
| multi_turn | 100% 多轮（平均 5.5 轮） | ~33.4M | 41.6%（90% 进 train） |
| shareai / muice / dailychat / agent | 闲聊 | ~1.3M | 2% |

单轮指令淹没了多轮结构 → 模型学到「一问一答即结束」。

### 机制 2：loss masking 把轮次转移从 loss 里删了（代码级确认）
`build_assistant_mask`（train.py）只对「模型：→用户：/块尾」之间的回复算 loss，
`用户：`/`模型：` 边界标签和用户内容全部 ignore_index=-100：
- 模型从没被训练预测「<eos> 之后接 用户：」→ 原始生成时 EOS 后无所适从，继续吐话术；
- 用户第二轮内容只作为 context 出现（mask 不影响 context），但欠训练 + 单轮主导下
  学不会对后续轮次的条件反应（健康检查 D 段：用户说"我其实还好"，模型无视继续推话术）。

## 修复（两个都进了新基线 run）

### 修复 1：数据重平衡（A1）
`prepare.py --task-ratio 0.25` → zhuangxialie 从 57% 降到 ~25%，对话占 ~74%。
- 附赠效果：train 73.9M → 41.8M tokens，1500 步覆盖率 33% → **60%**（固定步数预算下
  每 epoch 学得更充分，等于白赚一倍数据遍数）。
- val.bin 不变（只来自 4 个对话文件的固定 90/10 切分，seed 1337）→ 新旧系列 val 可比。

### 修复 2：mask 纳入轮次边界标签（D 修复）
`build_assistant_mask`：`用户：`[308,228] 与 `模型：`[306,228] 边界标签改为算 loss
（内容仍 mask）。模型学会「回复+<eos> → 下一轮 用户：」的对话骨架，原始生成能续轮。
单测通过（单轮+多轮混合序列 mask 正确，边界 4×2 + 回复 + EOS 有 loss）。
