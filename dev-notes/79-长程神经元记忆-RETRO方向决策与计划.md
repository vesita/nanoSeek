# dev-notes/79: 长程神经元记忆（NDB → RETRO 方向）决策与计划

日期：2026-09-10
前置：dev-notes/78（神经元级 NDB v5/v6 全记录）
关键词：no_grad store / 长程记忆 / chunk KV / cross-attention / RETRO / Memorizing Transformers

## 0. 决策（用户 2026-09-10）

> "如果不能超越 tdb，那么 ndb 其实就没什么意义。直接朝着可能超越 tdb 的方向前进，不然就放弃这个方向。"

- **放弃**「后缀键 + 梯度值 + 加性注入」的当前范式（§78.13 已证明：信息与 TDB 同源、通道更差）；
- **保留** no_grad store 这一核心约束；
- **转向**唯一可能携带 TDB 拿不到信息的形态：**长程 chunk KV + cross-attention 读取**。

## 1. 成功判据（先定义再动手）

⚠ 在**聚合 val loss** 上，长程记忆几乎不可能超过 TDB——该指标由局部位置主导，而 TDB 正是为局部优化的。所以判据分层：

| 层 | 指标 | 通过条件 |
|---|---|---|
| **主判据** | 长程依赖子集上的 Δ（依赖 >256 token 之外的信息） | NDB Δ 显著 > TDB Δ（TDB 在此 ≈0） |
| 副判据 | 聚合 val loss | NDB + TDB ≥ TDB（可叠加、不互相伤害） |
| **否决线** | 长程子集上 NDB 无增益 | 放弃 NDB 方向 |

**关键**：TDB 在长程子集上≈0（后缀看不到窗外），所以这不是"同一把尺子上比高低"，而是"比 TDB 结构上做不到的事"。

## 2. 架构（RETRO-lite）

```
每个 Transformer block:
  h = h + SelfAttn(h)                    # 原有
  Q = h · W_q                            # 用当前 h 查询
  K_mem, V_mem = NDB.retrieve(Q, top_k)  # no_grad store，近似 kNN
  h = h + CrossAttn(Q, K_mem, V_mem)     # 模型自己决定读多少
  h = h + FFN(h)                         # 原有
```

- **store**：`(key_emb, value_kv)`，写入 running mean / EMA，全程 no_grad；
- **可训**：只有 `W_q / W_k / W_v` + 门控；
- **检索粒度**：按 chunk（每 64 token 查一次），chunk 内 cross-attend（RETRO 的省算力技巧）；
- **键/值来源**：**当前窗口之外**的 chunk（同文档前文 / 语料其他位置）——这是与 TDB 的本质区别。

## 3. 分阶段

| 阶段 | 内容 | 判据 | 成本 |
|---|---|---|---|
| **B0** | 长程 headroom 诊断：这个基座/数据上，窗外信息到底能带来多少可预测性 | 有显著 headroom 才继续 | 小时级 |
| **B1** | chunk KV store（no_grad）+ cross-attention 模块 | 机制跑通、库能建 | 天级 |
| **B2** | 冻结基座训接口 → 解冻共训 | 长程子集 Δ 显著 > TDB | 周级 |
| **B3** | 巩固（蒸馏回权重）+ 运行时写入 | — | — |

**B0 是 go/no-go 闸门**：如果连"窗外信息能降低 loss"都测不出来，后面不用做。

### B0 结果（2026-09-10）：headroom 存在且很大 ✅

`local/longrange_probe.py`：同一批 target 区（最后 256 token），只变前置 context 长度 L−256；
对照 = 同长度但前置 context 换成别处随机 token。

| L | loss_short | loss_real | **Δ_real** | loss_rand | Δ_rand |
|---|---|---|---|---|---|
| 272 | 2.3522 | 2.3135 | **−0.0387** | 2.4625 | +0.1103 |
| 320 | 2.3522 | 2.2868 | **−0.0653** | 2.5337 | +0.1815 |
| **384** | 2.3522 | **2.2867** | **−0.0655** | 2.6571 | +0.3050 |
| 512 | 2.3527 | 2.5568 | +0.2041 | 3.4095 | +1.0568 |

**三条结论**：

1. **headroom 存在且很大**：给 64–128 个真实前置 token，loss 降 **−0.039 ~ −0.0655**；
2. **不是长度/位置伪影**：随机前置 context 反而变差（+0.11~+0.31）——收益完全来自真实内容；
3. **基座 RoPE 外推极限 ≈ 384**：超过就崩（L=512 的 Δ 转正 +0.20）。

**量级对比**：−0.0655 是 TDB（−0.015）的 **4.4×**、当前后缀 NDB（−0.0046）的 **14×**。

⚠ **口径说明**：这里的前置 context 是**紧邻**的（连续），严格说是"窗口太短 128 token"，
不是"远距离检索"。要验证真正的远距离检索，需要让基座能吃更长 context（或靠
cross-attention 把远处内容注入）。**但闸门已通过：长程方向有真实、可观的 headroom。**

⇒ 进入 B1。

## 4. 风险

1. **吸收**：键/值若在窗口内可算 → 共训必被吸收（**必须长程**）；
2. **检索 recall** 决定上限（需要 product-key / FAISS）；
3. **容量**：chunk KV 很大（64×512/块），要压缩（潜码）或分层；
4. **共训不稳定**：小模型 + 新模块容易塌，要 KL 锚定 + 分阶段解冻。

## 5. 与 TDB 的关系

不是替代，是**互补**：TDB 管局部续写，长程 NDB 管跨窗依赖。
主判据成立 → 两者叠加；长程子集上 NDB 无增益 → 整个 NDB 方向放弃。
